## 1. 问题描述（Bug 1）

个人主页的 Three.js 雨夜便利店场景中：**镜头一旦开始移动（滚动推进或 OrbitControls 拖拽），便利店的墙体和店内地板就开始闪动**；镜头静止时画面正常，看不出异常。

闪烁特征：

- 只在相机运动期间出现，静止后自行消失；
- 集中在便利店的**内墙表面**与**店内地面**，呈逐帧明暗/材质交替的"抖动"；
- 与主题（白天 / 夜晚）、雨量动效无关，排除了雨滴、玻璃雨痕、招牌呼吸闪烁等环境动效。

## 2. 问题定性：Z-Fighting（深度冲突）

该现象是图形学中典型的 **Z-Fighting**：场景里存在**两张（或多张）精确共面的面片**，它们都写入深度缓冲，深度测试无法稳定区分谁在前。

- 相机**静止**时：每帧投影出的深度值相同，深度测试的"赢家"逐像素固定，画面看起来稳定；
- 相机**移动**时：视图矩阵变化导致深度值逐帧微小漂移，浮点精度在共面面上无法分出胜负，**赢家逐帧翻转 → 表面闪烁**。

这正是"一旦镜头开始移动才闪"的教科书症状。全仓库确认：**没有任何地方使用 `polygonOffset` 或对数深度缓冲**来缓解共面。

## 3. 起因分析（根因定位）

罪魁是 `scene-builder.mjs` 中搭建的「店内内衬」——一个 `MeshToonMaterial({ side: THREE.BackSide })` 的倒扣房间盒子（`scene-builder.mjs` 第 165–169 行），它与外围结构**表面严丝合缝地贴在同一平面上**。

### 3.1 墙体闪动：内衬三面内墙 vs 外墙内表面

店体结构（`scene-builder.mjs` 第 171–173 行）：

```js
// 后墙、左墙、右墙都是实心 Box，厚度 STORE.wall = 0.12
box(storeW, STORE.h, STORE.wall, storeCx, STORE.h / 2, STORE.z0 + STORE.wall / 2, mats.building);
box(STORE.wall, STORE.h, storeD, STORE.x0 + STORE.wall / 2, STORE.h / 2, storeCz, mats.building);
box(STORE.wall, STORE.h, storeD, STORE.x1 - STORE.wall / 2, STORE.h / 2, storeCz, mats.building);
```

- 左外墙占据 x ∈ `[x0, x0 + wall]`，其**朝店内的一面落在平面 `x = x0 + wall`**；
- 右外墙内表面落在平面 `x = x1 - wall`；
- 后外墙内表面落在平面 `z = z0 + wall`。

店内内衬（`scene-builder.mjs` 第 165–169 行）：

```js
const roomZ0 = STORE.z0 + STORE.wall;   // 后侧从外墙内表面起算
const roomZ1 = STORE.z1 - 0.02;
const roomH = STORE.h - 0.06;
box(storeW - STORE.wall * 2, roomH, roomZ1 - roomZ0, storeCx, roomH / 2,
  (roomZ0 + roomZ1) / 2, mats.interior, false);
```

- 内衬盒宽 `storeW - 2 * wall`、居中摆放 → **左侧面恰好落在 `x = x0 + wall`，右侧面恰好落在 `x = x1 - wall`**；
- 内衬深度从 `z0 + wall` 起算 → **背面恰好落在 `z = z0 + wall`**。

结果：内衬的左、右、后三个内表面与对应外墙的内表面**完全共面**。两个面都朝向店内观察者（外墙内表面 FrontSide 可见，内衬 BackSide 从店内也可见），**共面 + 都写深度 + 材质不同** → 透过 storefront 玻璃看进去时，内墙表面逐帧互相打架。

### 3.2 地板闪动：内衬底面 vs 底座顶面

- 底座：`slab(BASE, BASE, 0, 0, 0, BASE_THICKNESS, mats.base)`（第 128 行），按「顶面高度」摆放 → **顶面在 y = 0**；
- 内衬：`cy = roomH / 2`、高度 `roomH` → **底面也在 y = 0**。

整个便利店投影范围内，两张 y = 0 的面完全共面 → 店内地板闪动。

### 3.3 次要放大因素（非根因，但加剧观感）

1. **描边线与面共深度**：`materials.outline()` 用 `EdgesGeometry` 生成的 `LineSegments` 与盒子表面严格同深度（`materials.mjs` 第 212–218 行）。镜头移动时墙棱线会与墙面发生线/面深度争夺，让"边缘闪烁"更明显。
2. **路面贴花 vs 湿地面 Reflector（仅车行道，非店内）**：斑马线 / 停车位列在 `y = 0.022`（`scene-builder.mjs` 第 142–145 行），Reflector 湿地面在 `y = 0.02`（`rain-system.mjs` 第 292 行），仅差 2 mm——若车行道也出现闪烁，这是第二个来源。

### 3.4 已排除的方向

| 怀疑对象 | 排除依据 |
|---|---|
| 雨滴 / 波纹 / 玻璃雨痕 | 材质均 `depthWrite: false`，且不与墙面共面 |
| 招牌 emissive 呼吸 / 掉电 | 只影响 `sign` 材质亮度，不产生逐帧表面翻转，且与相机移动无关 |
| 主题切换换色 | 闪烁在单一主题内随相机运动复现 |
| 阴影 acne | 场景未启用 shadow map |
| 湿地面 Reflector 本身 | 区域在车行道（cz ≈ 2.75），不覆盖店内地板 |

## 4. 解决方案

按侵入性从小到大给出三个方案；**方案 A 与 B 二选一即可解决根因**，方案 C 为可选加固。

### 方案 A（推荐）：内衬盒整体缩进 1–2 mm

把内衬的宽 / 深 / 高各缩小 epsilon（或中心微移），让内衬与外墙、底座在三个方向上都脱开几毫米：

```js
// scene-builder.mjs —— 店内内衬
const EPS = 0.002; // 2mm，足以在本场景景深（near 0.1 / far 100）下分出胜负
const roomZ0 = STORE.z0 + STORE.wall + EPS;          // 后侧脱开外墙内表面
const roomZ1 = STORE.z1 - 0.02;
const roomH = STORE.h - 0.06;
box(storeW - STORE.wall * 2 - EPS * 2,   // 左右各缩 EPS
  roomH,
  roomZ1 - roomZ0,
  storeCx, roomH / 2 + EPS,               // 底面抬离 y = 0（底座顶面）
  (roomZ0 + roomZ1) / 2, mats.interior, false);
```

- 优点：改动一处、不动外墙与底座、不引入新材质属性；视觉上 2 mm 不可感知。
- 注意：底面抬高后，室内陈列（货架、柜台）仍立在 y = 0，会"嵌入"内衬地板 2 mm——被内衬底面挡住，反而形成正确的遮挡关系，无需同步移动陈列。

### 方案 B：材质级 `polygonOffset`

不改几何，给冲突材质加深度偏移，让深度测试人为偏爱其中之一：

```js
// materials.mjs —— interior 材质
interior: new THREE.MeshToonMaterial({
  color: "#f7efe2",
  gradientMap: ramp,
  side: THREE.BackSide,
  polygonOffset: true,
  polygonOffsetFactor: 1,   // 负值则是"推远"，按需二选一
  polygonOffsetUnits: 1
}),
```

- 需要给 `mats.interior`、（地板一侧的）`mats.base` 分别调 offset，保证**只有一方稳定胜出**；
- 优点：零几何改动；缺点：offset 值与观察角度无关但与深度精度耦合，换 `near/far` 或大场景时可能需要回调。

### 方案 C（可选加固）：描边线与路面贴花

1. **描边线**：给 `outlineMaterial` 加 `polygonOffset: true, polygonOffsetFactor: 1, polygonOffsetUnits: 1`，让线稳定浮在面之上（或接受轻微成本，维持现状——棱线闪烁通常比面闪烁轻微）。
2. **车行道贴花**：把 Reflector `area.y` 从 `0.02` 下调到 `0.016`，或把贴花抬到 `0.026`+，保证贴花、湿面、路面三者各自拉开 ≥ 2 mm。

## 6. 第二轮残留：左右立柱闪动（红圈标注，待修）

> 2026-09-23 用户截图标注：红圈位于**便利店右侧橱窗立柱**——从雨棚右角竖直向下到地面的那条立带（竖门框、右外墙、横梁右端、雨棚右角的交汇处）。以下为识别结论与修复方案；**已按方案 D 于 2026-09-23 执行修复**。

### 6.1 问题描述

第一轮修复（方案 A 缩内衬 + 删两根竖门框描边）后，店内墙体与地板不再闪；但镜头移动时，**红圈内的右侧立柱仍闪动**。左侧对称位置（左竖门框 + 左外墙 + 横梁左端）几何完全相同，图中未圈但必然同闪。

### 6.2 起因识别：storefront trim 与结构墙共用同一 x 区间

坐标回顾：`STORE = { x0: -1.0, x1: 3.0, z0: -2.6, z1: 0.6, wall: 0.12 }`。

红圈处交汇的几何（`scene-builder.mjs`）：

| 部件 | 行号 | 占据范围 |
|---|---|---|
| 右外墙 | 178 | x ∈ **[2.88, 3.0]**，z ∈ [-2.6, 0.6]（带 outline） |
| 右竖门框 trim | 217–219 | x ∈ **[2.88, 3.0]**，z ∈ [0.53, 0.67]（描边已删，**面片仍在**） |
| 横梁（门头框） | 211 | x ∈ [-1, 3]，**右端面落在 x = 3.0**，z ∈ [0.53, 0.67]（带 outline） |
| 雨棚 | 223 | 仅与上述体积相交，**无共面，非元凶** |

**共面冲突有两组：**

1. **面片 Z-Fighting（白/灰逐帧翻转）**——重叠区 z ∈ [0.53, 0.6] 内，右竖门框与右外墙：
   - **外侧面都落在平面 x = 3.0**：「街角」机位相机 x = 3.8 > 3.0，两面同时可见 → 打架；
   - **内侧面都落在平面 x = 2.88**：「橱窗」机位相机 x = 2.2 < 2.88，两面同时可见 → 打架；
   - 横梁右端面同样落在 **x = 3.0**（y ∈ [1.91, 2.05] 段），与墙、竖框外侧面**三方共面**。
   - 截图正处于「关于我」段（街角 → 橱窗过渡，相机 x 从 3.8 滑向 2.2），恰好先后穿过两个可见 regime——所以这条立柱持续闪。

2. **描边黑线残留**——上一轮**只删了两根竖门框的 outline**，右外墙（178）与横梁（211）的描边还在：它们在 x = 3.0 平面上的棱线（外墙前右竖棱、横梁右端棱）与竖门框外侧面共面 → 移动时闪**黑线**。

**与第一轮的关系**：同类根因（共面 Z-Fighting）、**不同位置**——第一轮方案 A 只缩了店内内衬，没有动 storefront trim 与外墙的 x 区间，因此这是独立的第二处。上一轮修复记录中亦有预警（"门框侧面与墙体共面的面片冲突"）。

### 6.3 解决方案（方案 D，推荐；已执行 2026-09-23）

**三根 storefront trim 在 x 向各缩进 2 mm**（中心不变），使 trim 的每个面与墙的对应面拉开 2 mm：

```js
// scene-builder.mjs（EPS 可直接沿用内衬修复时的 0.002）
// 竖门框 ×2：宽 wall → wall - 2*EPS（外面 x=2.998、内面 x=2.882，各离墙 2mm）
box(STORE.wall - EPS * 2, glassH + frameTop, 0.14,
  STORE.x1 - STORE.wall / 2, glassBottom + (glassH + frameTop) / 2,
  STORE.z1, mats.trim, false);   // 左侧同理
// 横梁：宽 storeW → storeW - 2*EPS（右端面 x=2.998，脱开 x=3.0）
box(storeW - EPS * 2, frameTop, 0.14, storeCx,
  glassTop + frameTop / 2, STORE.z1, mats.trim);
```

- trim 与墙的重叠段本就埋在墙体体积内，缩 2 mm 后仍埋在里面，**外观无感**；
- 描边黑线：墙/横梁棱线在 x = 3.0，竖框外侧面退到 2.998——从右侧看棱线在面**前方**、稳定胜出；从店内看竖框内面 2.882 挡住棱线，稳定遮挡。若墙/横梁描边仍有个别闪，再按方案 C 第 1 条给 `outlineMaterial` 加 `polygonOffset` 兜底；
- **不推荐**对 `mats.trim` 全局加 polygonOffset：该材质还用于灯杆、自行车、护栏等大量无冲突物体，副作用面大。

**左侧对称位置一并修**（同一改动覆盖左右两根竖框 + 横梁两端）。

### 6.4 验收补充

在 §5 基础上追加：

## 7. Bug 3：便利店门关闭状态存在缝隙

> 2026-09-23 用户截图标注：门洞左右两侧各有一条竖向缝隙（红圈），关门状态下可透出店内。

### 7.1 问题描述

自动门完全关闭（`doorProgress = 0`）时，门洞的两处竖向接缝——**左固定玻璃 ↔ 左门扇（x = 0.36）** 与 **右门扇 ↔ 右固定玻璃（x = 1.64）**——各出现一条可见竖缝，能透过缝隙看到店内；视角变化时缝的观感还会变。中缝（两扇门相接的 x = 1.0）不漏。

### 7.2 起因分析：门扇与固定玻璃错开 15mm，斜视线从接缝"漏"进店内

几何现状（`scene-builder.mjs` 第 206–209 行）：

| 面板 | x 跨度 | z 平面 |
|---|---|---|
| 左固定玻璃 | [-0.88, **0.36**] | `STORE.z1`（0.600） |
| 右固定玻璃 | [**1.64**, 2.88] | `STORE.z1`（0.600） |
| 左门扇 `door:left` | [**0.36**, 1.00] | `STORE.z1 + 0.015`（**0.615**） |
| 右门扇 `door:right` | [1.00, **1.64**] | `STORE.z1 + 0.015`（**0.615**） |

- **x 方向是零间隙精确对接**（0.36 / 1.64），所以正视没有缝；
- 但门扇整体比固定玻璃**向店外凸出 15mm**——相邻两块面板的竖边不在同一深度平面上；
- 斜视时，擦过门扇竖边的视线继续向店内前进 15mm 才到达固定玻璃平面，途中横向偏移 `δ = 15mm × tanθ`（θ 为视线与店门法线的夹角）。对接设计在 x 向的覆盖余量是 **0**，因此只要 `δ > 0`（任何斜角），就存在一条同时避开门扇与固定玻璃的视线通道 → **竖缝漏光**。θ = 45° 时逃逸带宽 15mm，街角 / 俯视机位完全够看；
- 两处红圈正是 x = 0.36 与 x = 1.64 两个接缝（约占玻璃立面 33% / 67% 位置）。

**为什么门要凸出 15mm（不能直接共面）**：开门时门扇横移 `DOOR_TRAVEL = 0.62m` 滑到固定玻璃正上方（`animation-loop.mjs`）。若门与固定玻璃同 z，开门过程两块玻璃在重叠区完全共面 → 直接复现 Bug 1 类型的 Z-Fighting。15mm 台阶是为躲开共面，代价就是关门斜视漏缝。

**顺带排除**：中缝 x = 1.0 处两扇门同 z、边线重合，无深度台阶，不漏；门底 6cm 区域不是红圈标注位置；方案 D 的立柱缩进与门扇 / 固定玻璃无关，未触及本问题。

### 7.3 解决方案

#### 方案 E（推荐）：门洞两侧加竖梃（mullion），把 15mm 台阶侧向通道堵死 —— 已执行 2026-09-23

在 x = 0.36 与 x = 1.64 各加一根细竖框（真实便利店门洞本来就有门侧竖梃，兼修 bug 兼补细节）：

```js
// scene-builder.mjs —— 玻璃面板之后、门框 trim 附近
const MULLION_W = 0.03;   // 宽 30mm（x 向 ±15mm 盖住接缝）
const MULLION_D = 0.013;  // 深 13mm：占 z ∈ [0.600, 0.613]
// 中心 z = STORE.z1 + MULLION_D / 2 = 0.6065，前表面 0.613，比门扇 0.615 退 2mm
box(MULLION_W, glassH, MULLION_D, innerX0 + fixedW, glassY,
  STORE.z1 + MULLION_D / 2, mats.trim, false);   // 左：x = 0.36
box(MULLION_W, glassH, MULLION_D, innerX1 - fixedW, glassY,
  STORE.z1 + MULLION_D / 2, mats.trim, false);   // 右：x = 1.64
```

- 射线要在 z ∈ [0.600, 0.613] 的台阶深度内、接缝 x 带里侧向穿过，必然撞上竖梃实心体 → 任意角度不漏；
- 前表面比门扇退 2mm：关门时门扇（0.615）在竖梃前方、不共面；开门时门扇滑到竖梃侧后方，同样不共面；
- `outlined: false`：竖梃紧贴门扇玻璃，免去棱线在门平面附近再生描边闪动；
- 视觉上是门洞两侧的固定门梃，开门后门扇收进竖梃后面，行为合理。

#### 方案 F（备选）：固定玻璃各向门洞内侧加宽 40mm，塞到门扇后面

左固定玻璃右缘 0.36 → 0.40、右固定玻璃左缘 1.64 → 1.60（z 仍 0.600，位于门扇后方）：

- 斜视逃逸带 `δ ≤ 40mm` 时被加宽段接住（覆盖到 θ ≈ 69°，远超实际机位）；
- 代价：关门时门扇与固定玻璃出现 40mm 水平重叠（前后差 15mm），玻璃叠玻璃依赖透明排序，偶发排序抖动；开门时重叠区更大，同理；
- **明确排除的错误方向**：把门改成与固定玻璃同 z——开门即共面 Z-Fighting（见 7.2）。

### 7.4 验收补充

1. 关门状态（大多数时间门是关的），从街角机位、俯视机位、左前 / 右前斜看门洞两接缝：**无漏光竖缝**；
2. 等一次门开合动画：开门过程中门扇与竖梃 / 固定玻璃无闪烁、无穿插共面闪动；
3. 中缝与门框其余部分无回归（Bug 1 / Bug 2 不复发）。
