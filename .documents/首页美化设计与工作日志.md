## 2. 思考分析

### 2.1 awesome design.md 是什么（网读结论）

- **DESIGN.md** 是 Google Stitch 提出的「纯文本设计系统文档」：一份 markdown，让 AI 代理读完即可生成视觉一致的 UI。
- **awesome-design-md** 仓库（MIT，73+ 个品牌）收录了真实网站的设计分析，每份包含 9 大板块：
  1. Visual Theme & Atmosphere（视觉主题与氛围）
  2. Color Palette & Roles（语义色板 + hex）
  3. Typography Rules（字体层级全表）
  4. Component Stylings（按钮/卡片/输入框等状态）
  5. Layout Principles（间距体系、栅格、留白哲学）
  6. Depth & Elevation（阴影系统、表面层级）
  7. Do's and Don'ts（设计红线）
  8. Responsive Behavior（断点、折叠策略）
  9. Agent Prompt Guide（给 AI 的提示词）

**启示**：本项目不是照抄某品牌，而是**先用 DESIGN.md 方法论产出一份「墨海寻珠」自己的设计系统文档（第 7 节）**，再按此实现 —— 这正是 awesome design.md 推荐的工作方式。

### 2.2 三个组件库的调研结论（已上网核实）

| 库 | 可借鉴的组件/效果 | 本站（静态 MkDocs）可落地形式 |
|---|---|---|
| **React Bits**（140+ 组件） | Aurora 极光背景、GradientText 渐变文字、TiltedCard 倾斜卡片、SpotlightCard 聚光灯卡、ScrollReveal 滚动显现、粒子背景 | 全部降级为 **纯 CSS keyframes + 原生 JS**（站点无 React，但效果原理通用） |
| **Aceternity UI** | Bento Grid 网格卡片、Spotlight 卡片、Timeline 时间线、3D 卡片、Hero 区块、HoverBorderGradient | Bento 布局用 CSS Grid；时间线用 flex + 渐变线；Spotlight 用 mousemove 原生 JS |
| **Uiverse.io**（3000+ 元素，MIT） | 玻璃拟态卡片、渐变光环头像、hover 动效、时间线、徽章 chip | 直接以 CSS/HTML 形态复用思路，样式自写以匹配主题色 |

**关键约束**：站点是 MkDocs + Material（静态站、已有樱花粉/深紫主题），无 React、无 Tailwind、无构建工具 —— 所有「React 组件」只能提取其**视觉与交互理念**，用 HTML + CSS + 少量原生 JS 实现。

### 2.3 站点现有基础（项目分析）

- 主题：Material，**樱花粉 primary + 深紫 accent**（亮色），暗色黑底粉链；支持明暗自动切换 ✅
- `docs/stylesheets/extra.css` 已挂载（当前为空注释）
- `docs/javascripts/` 已有 mathjax.js / mermaid.mjs / extra.js
- 历史文档已规划过「官方 home.html 模板方案」（custom_dir + overrides/home.html）**但未实施**，overrides 目录不存在
- 首页现有图片 5 张：我的照片1/2/3.jpg、大师合影.jpg、获奖证书.jpg（在 `docs/主页/`）

**方案决策**：放弃 overrides/home.html 全模板方案（内容写死在模板里，编辑成本高、无法参与全文搜索），改用 **HTML 分块嵌入 markdown + extra.css 定制 + 少量原生 JS**：
- 正文内容保留在 `index.md`，易于维护 ✅
- 内容仍参与站点搜索 ✅
- 页面级隐藏 TOC 用 frontmatter `hide: [toc]` ✅

### 2.4 设计方向定调

「墨海寻珠」= 知识如海、寻珠采撷。主题色已是樱花粉 × 深紫。定调为：

> **「书卷 × 樱色」编辑风**：衬线大标题（宋体系衬线字栈，不用外链字体）承载书卷气；樱花粉极光渐变背景 + 玻璃拟态卡片承载现代感；深紫作点缀强调 —— 暗色模式整体转墨色，粉色化为微光。

不引入外部字体（国内网络不稳 + 主题已用 Roboto），用系统字体栈：`Georgia, "Noto Serif SC", "Songti SC", "SimSun", serif` 用于展示标题；正文跟随主题默认。

```
│  ↓ 滚动提示                                      │
├────────────────────────────────────────────────┤
│  BLOCK 2 · 项目缘起（名字含义 + 三理由卡片）        │
│  [引文卡：「墨海」=… 「寻珠」=…]                  │

│  BLOCK 3 · 关于我（照片墙 + 兴趣标签）             │
│  [左侧 我的照片1 + 获奖证书 拼贴]  [右侧文字]       │
│  [兴趣 chip 云: 单机游戏/美剧/排球/羽毛球/蛙泳/…]   │
│  [特长卡: 上低音号（9年）]                        │

│  BLOCK 4 · 学历信息 → 垂直时间线                   │
│  2011育英小学 ─ 2017重庆一中初中 ─ 2020高中       │
│  ─ 2023北邮计算机 ─ 2025北邮数据科学(高亮"现在")   │
├────────────────────────────────────────────────┤
│  BLOCK 5 · 寄语与交流（收尾卡）                   │
│  「祝愿读到这些文字的你有所收获」+ 交流引导         │
└────────────────────────────────────────────────┘
```

设计要点：
- **节奏**：全宽 Hero → 紧凑引文 → 卡片网格 → 照片拼贴 → 时间线 → 收尾，避免「统一间距平铺」
- **层次**：Hero 是唯一大面积渐变区；以下区块回到纸张底，卡片用圆角+极浅阴影，靠「线条/圆点/渐变描边」而非大面积色块
- **动效克制**：仅 Hero 渐变漂移、打字机、滚动显现（IntersectionObserver）、卡片聚光跟随 —— 全部尊重 `prefers-reduced-motion`

### 6.3 字体层级
- 展示标题（Hero/区块标题）：`Georgia, "Noto Serif SC", "Songti SC", "SimSun", serif`，700，letter-spacing 微负
- 正文：随主题（Roboto/系统），`1.05rem`，行高 `1.8`（中文阅读）
- 标签/角标：12–13px，500，字距 `0.02em`

### 6.4 组件规范
- 卡片：`border-radius: 18px`；亮色 `border: 1px solid var(--nmd-line)`；阴影仅 `0 1px 2px` + hover 上浮 `translateY(-4px)` + 阴影加深（层级：卡片=纸，不重影）
- 按钮/链接：主题 accent 色；Hero CTA 用渐变胶囊按钮（樱粉→深紫）
- 徽章 chip：胶囊 999px，描边主题色 1px，底 15% 透明度主题色

### 6.5 布局原则
- 区块间距：`section` 级 `96px`，区块内 `32px`；内容列宽随主题容器（不强行全宽）
- 网格：Bento 用 `grid-template-columns: repeat(auto-fit, minmax(240px, 1fr))`
- 移动端 < 720px：Hero 头像置顶、照片墙单列、时间线缩距

### 6.6 Do's & Don'ts
- DO：明暗双套全 token；动效尊重 reduced-motion；图片 `loading="lazy"`（Hero 头像 eager）
- DON'T：不引入外部字体/CDN；不在每页加载大 JS（homepage.js 仅当存在目标元素才生效）；不做大面积实色块（保持纸面感）

## 9. Bug 修复记录（2026-08-11，第二轮）

### Bug 1：点击「主页」显示空白，刷新后正常

**现象**：从其他页面点击导航「主页」（`navigation.instant` 生效）→ 内容区空白；F5 刷新后正常。

**根因分析**（两步定位）：
1. **交互层面**：滚动显现机制 `.nmd-reveal { opacity: 0 }` 由 CSS 隐藏，靠 homepage.js 加 `is-visible` 显现。首页全部 5 个分块都挂了 `nmd-reveal`，含 Hero。
2. **主题机制层面**：`navigation.instant` 下点击链接是 XHR 替换内容区（`data-md-component` 容器），`extra_javascript` 里的脚本**只在整页加载时执行一次，instant 导航后不会重执行**（已核查 material 9.7.7 源码：无 `locationchange` 类完成事件可监听；`base.html:254` 注入的脚本不随 XHR 重跑）。
3. **叠加结果**：instant 替换后 CSS（首屏已加载，持续生效）仍在隐藏 `.nmd-reveal`，而 JS 不重跑 → 无 `is-visible` → 整页永远透明 → **空白**。刷新触发整页加载 → JS 正常跑 → 正常。

**修复方案**（双保险）：
- `docs/javascripts/homepage.js` 重构：
  - 抽出 `initHome()`（打字机/滚动显现/聚光跟随），以 `hero.dataset.nmdInit` 保证同一 DOM 实例只初始化一次；
  - 新增 `MutationObserver` 监听 `<html>`（永远不会被 instant 替换）下的节点插入——内容区被 XHR 替换后检测到新 `.nmd-hero` 即自动重新初始化；
  - 计时器与 IntersectionObserver 实例跨初始化清理（`clearTimeout` / `io.disconnect()`），防止重复叠加。
- `docs/stylesheets/extra.css` 第 8 节：隐藏态改为 `html.nmd-js .nmd-reveal` 作用域——`.nmd-js` 类由 homepage.js 同步添加，**任何 JS 未执行的场景都不会白屏**（无 JS 兜底）。

**验证**：本地起服务 + headless Chrome 跑「JS 先加载、内容后注入」的 harness（等价 instant 替换）→ hero 自动显现 `is-visible` ✅、打字机启动 ✅、视口外元素保持隐藏（滚动显现语义正确）✅。

### Bug 2：主页左侧导航栏不应显示

**根因**：首页 frontmatter 只写了 `hide: [toc]`，未隐藏左侧导航。

**修复方案**：`docs/index.md` frontmatter 增加 `navigation`（material 原生支持，`base.html:157` 会给 `.md-sidebar--primary` 加 `hidden` 属性）：

## 10. 第三轮优化（2026-08-11）：引文卡装饰 & 关于我图片排版

### 问题 1：引文卡的粉色「折线」飘到文字上

**现象**：项目缘起引文卡左上角有粉色折线浮在文字上。

**根因**：`.nmd-quote::before` 用 `content: "「"` 做装饰引号（衬线字体 3rem 渲染为粉色角括号，观感即「折线」），且受字体回退影响可能错位压到文字。

**修复设计**：去掉装饰引号，重新设计引文卡为「词条释义」结构：
- 引文卡改为 `--nmd-grad-soft` 渐变底 + 左侧 4px 渐变竖条（`::before` 实色条，不再有字形浮空问题）

## 13. 第六轮：关于我「只显示大师合影」真根因 + 我的照片 Coverflow 轮播

### 13.2 真根因诊断（推翻第五轮 GitHub Pages 结论）

用户明确「本地打开、与推送无关」，故第五轮的 GitHub Pages 编码假设不适用于本次。用 headless Chrome 对本地服务实测 `getBoundingClientRect`：

| 图片 | 修复前渲染 | 原因 |
|---|---|---|
| photo-1.jpg（第 1 行） | **figure 2x2（塌陷）** | 被 `:nth-child(even)` 误判为偶数行 |
| photo-master.jpg（第 2 行） | 280x210 正常 | 奇数行留在 `auto` 列 |
| photo-2.jpg（第 3 行） | **figure 2x2（塌陷）** | 同 photo-1 |
| certificate.jpg（特长卡） | 163x218 正常 | 不受 fig-row 影响 |

**根因**：`extra.css` 第 5 节 `.nmd-fig-row:nth-child(even) .nmd-fig-media { order: 2 }` 的奇偶选择器被 `<h2>` 标题干扰——section 第一个子元素是 `<h2>`（占第 1 位），导致第 1、3 个 fig-row 被误判为「偶数行」，图片被 `order: 2` 排进 `minmax(0, 1fr)` 弹性列，该列被长文本撑满后宽度为 0，`max-width: 100%` 把图片压成 0x0。非「照片太大」。

**修复**：`nth-child(even)` → `nth-of-type(even)`（只数同类型 div 兄弟，不受 `<h2>` 干扰），偶数行改为 `grid-template-columns: minmax(0, 1fr) auto` 列模板（图片留在 auto 列，永不被弹性列压塌）。

### 13.3 迭代实现记录

## 14. 第七轮：Hero 全屏化（首屏沉浸式）

### 需求

### 分析（MkDocs Material 布局实测数据）

- 页面结构：`<header>`（sticky，top:0，2.4rem）→ `.md-tabs`（非 sticky，随滚动滚走，仅 ≥1220px 显示）→ `.md-main` → `.md-main__inner.md-grid`（61rem 居中，margin-top 1.5rem）→ `.md-content__inner`（左右 1.2rem 边距 + padding-top .6rem + `::before` 高 .4rem）→ `.nmd-hero`

- 全屏方案：`width:100vw + margin-inline:calc(50% - 50vw)` 破容器（文章列水平居中、边距对称，50% 与 -50vw 恰好抵消）——数学已验证
- 两个易错点：
  1. **100vw 滚动条问题**：100vw 含滚动条宽度而布局视口不含（经典滚动条系统差 15~17px），纯 CSS 无法感知 → JS 写入 `--nmd-sb`
