## 1. 目标定义

本次首页升级目标为五项：

1. 电影片头式开场
2. 单镜头推进感
3. 玻璃霓虹 + 暗部留白
4. 强节奏转场（开门 / 翻牌 / 擦除）
5. 首屏结束后回归可读性内容流

一句话定位：

“不是堆特效，而是用一个有节奏的首屏短片，带用户进入知识内容。”

## 2. 现状与差距

### 2.1 已有基础（可复用）

- 全屏 Hero、明暗 token、主题配色已建立
- Aurora 背景、渐变标题、打字机、滚动显现、卡片聚光已具备
- 图片轮播与 reduced-motion 降级机制已有

### 2.2 主要差距

- 动效“并列”较多，缺少统一时间轴
- 缺少镜头语言（推进、景深、遮罩）
- 缺少“片头结束 -> 正文阅读”的明确转场闭环

结论：

当前是“炫酷组件集合”，下一步应升级为“片头叙事系统”。

## 4. 分镜时间轴（首屏 9 秒）

建议总时长 8~10 秒，默认 9 秒。

### Phase A（0.00s - 1.20s）冷开场

- 背景近黑，仅保留低频光感
- 轻微扫描线或噪点（克制）
- 主标题尚未完全显影

### Phase B（1.20s - 3.40s）显影建立

- 标题从 blur + opacity 渐入
- 头像光环建立，副标题进入
- 徽章/CTA 仍抑制，避免抢焦点

### Phase C（3.40s - 5.80s）单镜头推进

- Hero 整体轻推近（dolly-in 幻觉）
- 前中后景分层视差（近景快，远景慢）
- 视觉重心固定在标题与头像区域

### Phase D（5.80s - 7.20s）强节奏转场

- 三选一主转场：
	- 开门（split-door reveal）
	- 翻牌（card-flip wipe）
	- 擦除（directional mask wipe）
- 要求：同一时刻只保留一种主语法

### Phase E（7.20s - 9.00s）回归内容流

- 动效密度下降约 70%
- 项目缘起区块接管视觉主导
- 阅读节奏优先，卡片动效仅保留 hover 级反馈

## 6. 可直接使用的提示词

### 6.1 英文版（主提示词）

Design a cinematic personal homepage hero with a title-sequence opening.
Use a single-take push-in feeling with layered parallax depth.
Visual style: neon glassmorphism on a dark low-key canvas with intentional negative space, soft volumetric glow, and high-contrast typography.
Create rhythmic transitions: split-door reveal, card-flip wipe, and directional mask wipe, synced to a clear motion beat.
The first screen should feel like a film intro, then gracefully hand off into a calm readable editorial content flow.
Keep motion meaningful, not noisy.
Prioritize transform and opacity based animations for performance.
Respect reduced-motion preferences and provide an elegant static fallback.
Output should be production-ready for a static documentation site using HTML + CSS + vanilla JavaScript, no React dependency.

### 6.2 中文版（主提示词）

请设计一个电影片头感的个人主页首屏。
首屏采用单镜头推进体验，使用多层视差形成景深。
视觉风格为暗色留白上的玻璃霓虹质感，配合柔和体积光和高对比文字层级。
转场必须有强节奏，包含开门、翻牌、擦除三类语法，并用统一节拍串联。
首屏在完成片头叙事后，要自然过渡到可读性优先的正文内容流。
动效要有目的，不要噪音式堆叠。
优先使用 transform 与 opacity，保证性能。
必须支持 reduced-motion，并提供优雅静态降级。
实现约束为静态站可落地方案：HTML + CSS + 原生 JavaScript，不依赖 React。

## 7. 提示词增强短语库（按需拼接）

### 7.1 镜头感增强

Use a continuous camera path illusion, subtle dolly-in, and layered depth cues with near-mid-far motion differentials.

### 7.2 玻璃霓虹增强

Use translucent glass panels with edge highlights, neon accents in pink-violet-cyan, and restrained bloom on dark matte backgrounds.

### 7.3 转场增强

Transitions must feel editorial and intentional, with one dominant transition per phase and no overlapping competing transitions.

### 7.4 可读性增强

After the hero sequence, reduce animation density by 70%, increase text contrast, and prioritize scanning rhythm for long-form reading.

### 7.5 工程落地增强

Keep first meaningful paint clean, cap heavy effects to hero only, and avoid continuous full-page expensive animations.

## 8. 技术边界与实现约束（针对本项目）

项目约束：

- 站点框架为 MkDocs Material
- 首页内容以 docs/index.md 为核心
- 样式集中在 docs/stylesheets/extra.css
- 交互集中在 docs/javascripts/homepage.js
- 不依赖 React / Tailwind / 构建链重构

实现原则：

1. 首屏强动效仅限 Hero 区
2. 正文区只保留轻量反馈（hover / reveal）
3. 动画属性优先 transform、opacity、filter
4. reduced-motion 必须全链路可用
5. 保持明暗主题 token 一致性

---

## 9. 性能预算（建议）

- 首屏额外 JS：<= 40~60KB（压缩后）
- 首屏核心动画时长：8~10 秒
- 首屏持续高频动画对象：<= 4 类
- 首屏结束后 CPU/GPU 压力显著下降

禁止项：

- 不在全文区持续运行高成本粒子
- 不引入无降级的重型 WebGL 依赖
- 不让多个主转场同屏竞争

---

## 10. 验收标准（设计层）

满足以下条件视为设计达标：

1. 用户首次进入首页，能够明显感知“片头开场”而非普通 Banner
2. 视觉焦点在首屏时间轴中始终可追踪
3. 开门/翻牌/擦除至少有一种呈现明确且不混乱
4. 首屏结束后阅读感显著提升，不被持续动效干扰
5. 在 reduced-motion 下页面仍完整、优雅、可读

---

## 11. 后续实施建议（不改代码阶段后的下一步）

建议按三阶段推进：

1. Phase 1（低风险）：统一首屏时间轴 + 单一主转场
2. Phase 2（增强）：加入分层视差与镜头推进
3. Phase 3（打磨）：节拍校准、细节统一、性能压测

每阶段完成后都进行一次：

- 明暗主题验证
- reduced-motion 验证
- 移动端验证
- 首屏性能验证

---

## 12. 设计结语

本定稿的核心不是“多”，而是“准”：

- 准确的镜头语言
- 准确的节奏编排
- 准确的阅读回落

这样首页才能同时具备：

- 第一眼惊艳
- 第二眼舒服
- 第三眼愿意读下去
