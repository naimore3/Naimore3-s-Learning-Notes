# 墨海寻珠首页实施任务清单（电影片头风）

> 对应设计定稿：.documents/首页设计定稿_电影片头风.md
> 
> 目标：将“电影片头式首屏”以低风险、可回滚、可验证的方式落地到现有 MkDocs 首页。
> 
> 约束：先做结构化实施，不引入 React，不改站点框架。

---

## 0. 实施策略

采用三阶段推进，每阶段都必须可独立上线：

1. Phase 1：时间轴统一 + 单一主转场（低风险）
2. Phase 2：镜头推进 + 多层视差（增强）
3. Phase 3：细节打磨 + 性能压测（收尾）

每阶段结束必须执行四类验证：

- 明暗主题验证
- reduced-motion 验证
- 移动端验证
- 首屏性能验证

---

## 1. 文件映射（改动边界）

### 1.1 docs/index.md

职责：

- 保持内容结构语义化
- 为首屏阶段元素提供稳定钩子 class
- 预留转场遮罩层与分层容器

必备节点：

- Hero 外层容器（场景容器）
- 前景层/中景层/背景层占位
- 转场遮罩层（开门/翻牌/擦除三选一先实现一类）
- 首屏结束锚点（用于落地正文）

### 1.2 docs/stylesheets/extra.css

职责：

- 时间轴关键帧与状态类
- 分层视觉与材质系统
- 转场动画语法
- reduced-motion 全量降级

必做分区：

1. 时间轴状态类（phase-a 到 phase-e）
2. Hero 分层样式（near / mid / far）
3. 转场样式（先一种）
4. 正文回落样式（动效密度降低）
5. 响应式与可访问性降级

### 1.3 docs/javascripts/homepage.js

职责：

- 统一首屏主时间轴调度
- 在 navigation.instant 下保证可重复初始化
- 生命周期清理（定时器、观察器、事件）

必做能力：

- 单一入口 initHeroSequence()
- 相位切换控制（A/B/C/D/E）
- 用户交互中断策略（滚动、点击跳过）
- reduced-motion 直达正文策略

## 2. Phase 1（低风险）任务清单

目标：先把“有节奏片头”跑通，不追求复杂视觉。

### 2.1 页面结构任务

- 在 Hero 区添加场景状态容器 class（不改变既有文案）
- 增加转场遮罩节点（先支持开门）
- 增加“跳过片头”按钮（可选，但建议）

验收：

- 首屏结构完整，语义无破坏
- 未启用脚本时页面仍可正常阅读

### 2.2 样式任务

- 新增 phase-a 到 phase-e 状态样式
- 为标题、头像、按钮定义进入顺序
- 新增开门转场关键帧
- 定义正文回落态（降低动画/高亮强度）

验收：

- 9 秒内可见完整片头节奏
- Phase E 后视觉稳定，便于阅读

### 2.3 脚本任务

- 实现统一时间轴调度（setTimeout 或 rAF）
- 支持 instant 导航重新进入首页后重播
- 支持中断与清理，避免重复绑定

验收：

- 来回切页 5 次无叠加 bug
- 无控制台报错

---

## 3. Phase 2（增强）任务清单

目标：加入单镜头推进和景深层次。

### 3.1 视觉层次任务

- 背景层（远景）：慢速漂移
- 中景层（主体）：轻微 push-in
- 前景层（光效/颗粒）：极低透明点缀

验收：

- 明显感知“镜头推进”
- 不出现眩晕或阅读障碍

### 3.2 交互任务

- 鼠标/滚动对视差影响限幅
- 非首屏滚动时自动降低视差强度

验收：

- 移动端触控不抖动
- 高刷屏与普通屏均平滑

---

## 4. Phase 3（打磨）任务清单

目标：风格统一、性能达标、细节收束。

### 4.1 节奏统一

- 动画时长统一到节拍网格（0.4/0.8/1.2/2.4s）
- 缓动曲线统一（避免每元素各自为政）

### 4.2 可读性回落

- 首屏结束后降低 glow 与对比冲突
- 正文字号/行高/间距稳定为阅读优先

### 4.3 性能优化

- 控制持续动画对象数量
- 减少大面积高斯模糊重绘
- 仅 Hero 使用重动效，正文区轻交互

验收：

- 首屏完成后页面 CPU/GPU 压力明显下降
- 动效观感高级但不“吵”

---

## 5. 动效语法优先级

首发只实现一种主转场，建议顺序：

1. 开门（split-door）
2. 擦除（directional wipe）
3. 翻牌（card-flip）

原因：

- 开门最稳，视觉语义清晰
- 对静态站实现成本最低
- 最容易做 reduced-motion 降级

---

## 6. 关键风险与规避

### 风险 1：动画过载导致“炫但难读”

规避：

- 限制同时运动元素数量
- 强制 Phase E 回落

### 风险 2：instant 导航重复初始化

规避：

- 继续沿用数据标记与观察器清理机制

### 风险 3：移动端性能波动

规避：

- 小屏降级 blur、减少粒子和阴影
- 触控设备禁用高频鼠标跟随逻辑

### 风险 4：无障碍可用性不足

规避：

- 全量支持 prefers-reduced-motion
- 保证键盘可达与文本对比度

---

## 7. 实施前检查清单

- 设计定稿已确认
- 视觉关键词已固定
- 主转场已选定（建议开门）
- 验收标准明确
- 回滚策略明确（仅回滚 Hero 新增层和 phase 样式）

---

## 8. 完成定义（DoD）

满足以下条件视为本轮完成：

1. 首页进入后出现完整片头节奏（A->E）
2. 至少一种强节奏转场可稳定复现
3. 首屏结束后正文阅读体验明显优于首屏
4. reduced-motion 下自动降级且不破版
5. 明暗主题与移动端均通过

---

## 9. 备注

当前环境存在 mkdocs 命令不可用记录（exit code 127）。
实施时若需本地构建验证，可在可用环境执行：

- mkdocs build --clean
- mkdocs serve

若当前终端不可用 mkdocs，可先完成代码与静态检查，再由本地可用环境补充构建验证结果。
