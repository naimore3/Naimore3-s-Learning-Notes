## 0. 设计读法

Reading this as: **个人学习笔记首页的沉浸式首屏，面向愿意慢慢观看场景的访客，使用三渲二 / 日式二次元雨夜夜景语言，落地为一个可旋转、缩放、拖拽的 Three.js 微缩模型，并让滚动驱动 2-3 个连续镜头。**

| 维度 | 判断 |
|---|---|
| 页面位置 | 首页首屏或整个首页的固定背景层 |
| 场景类型 | 微缩模型 / 小型景观，正方形底座，第三视角 |
| 情绪 | 安静、治愈、都市夜晚孤独感，但仍温暖 |
| 视觉风格 | 三渲二、轮廓清晰、色彩柔和、夜景霓虹层次 |
| 交互 | 自由拖拽、旋转、缩放，同时滚动切换镜头 |
| UI 规则 | 场景内不绘制任何 HUD、按钮或提示文字 |
| 技术底座 | MkDocs Material + Three.js + 原生 JS，不引入 React 或完整游戏框架 |

## 1. 一句话定义

> 做一个可以捧在手里观察的雨夜便利店街角微缩世界：室外冷蓝潮湿，店内暖黄明亮，整个场景像被定格在日式动画里，既有收藏模型的精致感，也有细微的雨、光和水面动态。

## 2. 画面总布局

### 2.1 正方形底座

- 底座采用完整的正方形，建议边长约 `7.2m`，厚度约 `0.18m`。
- 底座边缘做轻微倒角，像手办地台或建筑模型展台。
- 底座本身不画 UI，只作为承载街道、建筑和道具的统一地面。
- 地面分成人行道、车行道、斑马线、排水沟、积水区和小巷入口。

### 2.2 街角转折

- 便利店位于底座的视觉中心偏后位置，面对镜头的主立面尽量完整。
- 街道从便利店左侧向右后延伸，形成明确的街角转折。
- 右侧或左后方保留一条狭窄小巷入口，增加社区夜晚的纵深。
- 车行道不宜过大，保持“小型景观”的紧凑感，不要做成完整城区。

### 2.3 构图层次

1. 前景：人行道、地面积水、斑马线、护栏、排水沟。
2. 中景：便利店门面、玻璃橱窗、自动门、招牌、雨棚。
3. 近侧道具：自动贩卖机、自行车、雨伞架、垃圾桶、路牌。
4. 背景：路灯、电线杆、电线、空调外机、公告栏、小巷入口。
5. 环境：持续降雨、地面反光、暖色室内光、远处交通信号灯。

## 4. 美术风格

### 4.1 三渲二原则

- 使用 `MeshToonMaterial` 作为主要材质，配合程序化 `gradientMap`，让明暗过渡呈阶梯状，而不是光滑写实渐变。
- 建筑和道具用清晰的深色轮廓线，轮廓颜色建议使用低饱和墨蓝黑，不用纯黑死边。
- 材质保持干净、简洁，不做过多脏迹；湿润感只出现在玻璃、地面和金属表面。
- 颜色柔和但要有夜景霓虹层次：室外冷蓝、店内暖黄、招牌霓虹青 / 粉 / 白。

### 4.2 轮廓线方案

优先方案：

1. 对主体建筑、道具和路牌使用 `EdgesGeometry` + `LineSegments`，按模型构建时自动生成。
2. 对圆润物体使用背面放大的“反向外壳法”，制作厚度均匀的描边。
3. 如果两种方案在某些道具上过重，再退回 `EffectComposer` + `OutlinePass`，但只用于少量主视觉。

这样可以避免依赖外部 SVG 或 PNG 描边资源。

### 4.3 色调：白天雨天 / 夜晚雨天双套

场景按 Material 主题的明暗模式切换两套天气光线，几何、构图与镜头完全共用，只换光照与配色：

| 模式 | 场景 | 口径 |
|---|---|---|
| 亮色（默认） | **白天雨天** | 阴天亮灰蓝天光、湿滑路面反光、店内暖光仍亮着；整体保持浅色阅读体验，正文对比度按 WCAG AA 校验 |
| 暗色 | **夜晚雨天** | 设计稿的冷蓝雨夜 + 霓虹招牌 + 店内暖黄，与室外形成冷暖对比 |

夜晚雨天的色调（对应亮色模式无关）：

| 区域 | 主色方向 | 作用 |
|---|---|---|
| 室外天空 / 背景 | `#0f1626` 到 `#1d2a45` | 冷色雨夜 |
| 地面与建筑 | `#2b3446`、`#3a4458` | 湿润暗色基底 |
| 霓虹招牌 | 青、粉、暖白 | 视觉焦点 |
| 街灯与车灯 | 暖黄、淡蓝 | 局部提亮 |
| 店内 | 暖白 `#fff1d6`、货架亮色 | 与室外形成冷暖对比 |
| 雨与积水 | 蓝白高光 | 湿滑反射 |

白天雨天的色调：

| 区域 | 主色方向 | 作用 |
|---|---|---|
| 室外天空 / 背景 | `#bcc9d9` 到 `#eaf0f6` | 阴天天光 |
| 地面与建筑 | `#b7c3d2`、`#dee5ed` | 湿滑浅灰蓝路面 |
| 远景楼宇 | `rgba(62, 82, 112, 0.2)` | 雨雾中的城市剪影 |
| 店招与霓虹 | 暖橙 `rgba(255, 180, 102, 0.55)`、粉红 `rgba(255, 42, 109, 0.18)` | 白天仍亮着的招牌，保留赛博点缀 |
| 雨与积水 | 灰蓝雨丝 `rgba(74, 100, 138, 0.3)` + 白色水光 `rgba(255, 255, 255, 0.4)` | 白天可见的雨与反光 |

两套 tokens 都集中在 `extra.css` 第 1 节的 `--nmd-sky-* / --nmd-ground-* / --nmd-city / --nmd-wet / --nmd-rain* / --nmd-shop*` 里，切换或微调只改这些变量。

## 5. 三个滚动场景设计

### 5.1 场景一：全景微缩模型（scroll progress 0.00-0.34）

**镜头任务**：先让人意识到这是“一个完整、可收藏的微缩世界”。

- 相机位于高处，约 `(5.2, 4.6, 5.2)`，从斜上方俯瞰整个正方形底座。
- 目标点约 `(0, 0.8, 0)`，确保便利店、街道和底座边界完整进入画面。
- 视场角约 `42°`，景深宽阔，模型感强。
- 背景尽量弱化，让底座轮廓和城市小景成为主体。
- 动效重点：持续降雨、地面积水反射、招牌和灯箱轻微闪烁。

### 5.2 场景二：街角平视与便利店门面（scroll progress 0.35-0.70）

**镜头任务**：从“看模型”过渡到“站在雨夜街角”。

- 相机下降到约 `(3.8, 1.7, 3.2)`，接近人眼高度，略微仰视店招。
- 目标点约 `(-0.2, 1.3, -0.6)`，重点落在便利店门面、玻璃橱窗、自动门和雨棚。
- 视场角约 `38°`，让前景的自动贩卖机、自行车、雨伞架形成景深。
- 地面反光更明显，玻璃上能看到雨水滑落。
- 自动门偶尔开合，露出部分店内暖光。

### 5.3 场景三：橱窗内景（scroll progress 0.71-1.00）

**镜头任务**：贴近大玻璃窗，让人清楚看到明亮、充实的便利店内部。

- 相机移动到约 `(2.2, 1.5, 2.4)`，并转向店内。
- 目标点约 `(0.4, 1.2, -1.2)`，穿过玻璃看向货架、饮料柜、收银台和关东煮柜台。
- 视场角约 `50°`，像站在窗外向内张望。
- 玻璃材质减弱镜面感，保证内部陈列清晰可见。
- 可让自动门短暂打开，或让镜头稍微横移，增强“窥视”叙事。
- 动效重点：店内暖光稳定、饮料柜灯箱微亮、关东煮热气可选、玻璃雨痕持续下滑。

### 5.4 镜头过渡

三个场景之间不要硬切，使用 `CatmullRomCurve3` 或分段贝塞尔曲线插值相机位置，并同步插值目标点和视场角。过渡时保持 `easeInOutCubic`，避免忽快忽慢。滚动进度计算统一为 `0-1`，由页面滚动距离映射。

## 6. 交互设计

### 6.1 滚动驱动镜头

- 将首页首屏或整个场景容器映射到一个 `scrollProgress`。
- 使用 `requestAnimationFrame` 主循环读取当前滚动进度，而不是在 `scroll` 回调里逐帧更新矩阵。
- `IntersectionObserver` 只负责判断场景是否在视口内，离开视口时暂停渲染，减少开销。
- 滚动只推进基础镜头路径；用户拖拽和缩放在基础镜头之上叠加。

### 6.2 自由拖拽、旋转、缩放

- 使用 `OrbitControls`，开启阻尼。
- 关闭平移，或把平移限制在模型附近，避免把场景拖出视野。
- 限制旋转角：水平偏移约 `±22°`，俯仰角约 `30°-80°`。
- 限制缩放：最近距离能看清橱窗，最远距离能看全底座。
- 用户交互结束后，镜头缓慢回到当前滚动进度对应的基础镜头。

### 6.3 无 UI

- 场景内不绘制提示、图标、进度条、按钮或文字 HUD。
- 浏览器和 MkDocs 自身导航保留在场景之外。
- 如果后续需要“继续浏览”的入口，只放在场景之外的内容层，不放入 3D 画面。

## 7. 基础动效清单

| 动效 | 触发方式 | Three.js 实现方向 | 降级 |
|---|---|---|---|
| 持续降雨 | 常驻 | `THREE.Points` + 程序化雨滴贴图 + 粒子下落 | 降为静止雨丝 |
| 屋檐滴水 | 常驻 | 少量实例化水滴沿屋檐边缘下落 | 静止 |
| 地面积水波纹 | 常驻 | 圆形波纹使用 `InstancedMesh` 或 shader 动画 | 静止水痕 |
| 招牌或灯箱闪烁 | 随机循环 | emissive 强度随时间轻微波动 | 恒定亮度 |
| 自动门开合 | 随机间隔 | 门板 `position` / `rotation` 插值 | 保持关闭 |
| 玻璃雨水滑落 | 常驻 | CanvasTexture 中雨痕做 UV 滚动 | 静止雨痕 |
| 地面灯光反射 | 常驻 | `Reflector` 或低粗糙度湿面材质 | 静态高光 |
| 远处交通信号灯变化 | 慢循环 | 发光材质颜色在红绿间切换 | 常亮 |

## 8. 技术方案总览

### 8.1 推荐技术栈

- `three`：核心场景、相机、灯光、材质、粒子。
- `three/addons/controls/OrbitControls.js`：旋转、缩放、阻尼。
- `three/addons/objects/Reflector.js`：地面或橱窗反射。
- 原生 `CanvasTexture` / `DataTexture`：生成店招、海报、标签、路面标线和雨痕。
- 原生 CSS：只负责容器定位和响应式。
- MkDocs `extra_javascript`：加载并初始化场景。

不引入 React、Vue、Tailwind 或完整游戏引擎。

### 8.2 文件规划

```text
docs/
  javascripts/
    three/
      convenience-scene.mjs          # 场景主入口
      scene-builder.mjs              # 底座、建筑、街道、道具搭建
      interior-builder.mjs           # 店内货架、设备、收银台
      materials.mjs                  # 三渲二材质、轮廓线、玻璃、湿地面
      canvas-textures.mjs            # 程序化生成所有文字和标线贴图
      rain-system.mjs                # 雨、水滴、波纹
      camera-rig.mjs                 # 滚动镜头路径与 OrbitControls
      animation-loop.mjs             # 动效更新与可见性控制
  stylesheets/
    convenience-scene.css            # 容器与响应式
```

如果希望减少文件数量，也可以合并成 1-2 个模块，但上面的拆分更利于后续调整。

> 后续收敛（见第 14.1 节）：`convenience-scene.css` 不再单独新建——容器、canvas 与降级层的样式继续写在 `docs/stylesheets/extra.css` 第 3 节，避免为同一个容器维护两份样式表；JS 模块仍按上面的拆分推进。

### 8.3 加载方式

**已定口径：本地 vendor，运行时不联网。** 具体环境配置、命令与远端部署步骤见 [Three.js开发环境与部署配置.md](Three.js开发环境与部署配置.md)；这里只保留接入形态：

```html
<script type="importmap">
  {
    "imports": {
      "three": "./javascripts/vendor/three/build/three.module.js",
      "three/addons/": "./javascripts/vendor/three/examples/jsm/"
    }
  }
</script>
```

注意 import map 的 **取值**必须写成 `./javascripts/...` 这样的 URL 形式：省略 `./` 会被浏览器当成裸标识符并整条忽略（Console 会提示 `Ignored an import map value of "three"`，场景随即退回显式 vendor 路径）。

`three@0.160.0` 由 conda 环境 `naimore3-docs` 里的 npm 取下来，拷进 `docs/javascripts/vendor/three/` 并提交进仓库（含 MIT `LICENSE`），因此构建与部署都不依赖 Node，也不请求任何 CDN。因为不制作 SVG / PNG 图片，唯一需要的外部文件就是 Three.js 运行时本身。

## 9. 程序化资源方案，不使用 SVG / PNG 美术图片

这是本方案的关键约束。所有可见内容都由几何、材质或运行时贴图生成。

### 9.1 建筑与道具

- 建筑：`BoxGeometry`、`ExtrudeGeometry`、`ShapeGeometry`。
- 电线：`TubeGeometry` 或分段圆柱。
- 自行车：多个圆柱和圆环组成，不追求真实模型，只追求剪影清楚。
- 货架、饮料柜、收银台：小尺寸盒体和发光面。
- 圆角道具优先使用 `BoxGeometry` 加小倒角材质，而不是外部模型。

### 9.2 文字与海报

店招、路牌、海报、自动贩卖机标签、店内价格牌全部使用 `CanvasTexture`：

```js
const canvas = document.createElement("canvas");
const ctx = canvas.getContext("2d");

canvas.width = 1024;
canvas.height = 256;

ctx.fillStyle = "#12233a";
ctx.fillRect(0, 0, canvas.width, canvas.height);
ctx.fillStyle = "#8ff4ff";
ctx.font = "bold 120px sans-serif";
ctx.textAlign = "center";
ctx.textBaseline = "middle";
ctx.fillText("コンビニ", canvas.width / 2, canvas.height / 2);

const signTexture = new THREE.CanvasTexture(canvas);
signTexture.colorSpace = THREE.SRGBColorSpace;
```

### 9.3 路面标线

斑马线、停车位、排水沟和地面导视用平面叠加 `CanvasTexture` 生成，不画 SVG / PNG。积水反光靠材质，不靠贴图。

### 9.4 三渲二渐变

用 1 像素高的 Canvas 生成 4-5 段色阶，作为 `MeshToonMaterial` 的 `gradientMap`：

```js
const ramp = document.createElement("canvas");
ramp.width = 256;
ramp.height = 1;

const rampCtx = ramp.getContext("2d");
const gradient = rampCtx.createLinearGradient(0, 0, 256, 0);
gradient.addColorStop(0.0, "#1b2434");
gradient.addColorStop(0.35, "#39445a");
gradient.addColorStop(0.7, "#8a93a6");
gradient.addColorStop(1.0, "#e8edf5");
rampCtx.fillStyle = gradient;
rampCtx.fillRect(0, 0, 256, 1);

const gradientMap = new THREE.CanvasTexture(ramp);
gradientMap.minFilter = THREE.NearestFilter;
gradientMap.magFilter = THREE.NearestFilter;
```

## 10. 材质、灯光与反射

### 10.1 材质分工

| 物体 | 推荐材质 | 原因 |
|---|---|---|
| 建筑、货架、路牌、道具 | `MeshToonMaterial` + `gradientMap` | 三渲二 |
| 玻璃橱窗 | `MeshPhysicalMaterial` 或透明 `MeshStandardMaterial` | 反射与透光 |
| 湿润路面 | 低粗糙度 `MeshStandardMaterial` + `Reflector` | 水光反射 |
| 灯箱、招牌 | `MeshToonMaterial` 或 `MeshBasicMaterial` + emissive | 夜景亮度 |
| 雨滴 | `THREE.PointsMaterial` + CanvasTexture | 柔和雨点 |
| 雨痕 | 玻璃材质叠加 CanvasTexture | 动态水流 |

### 10.2 灯光布置

- 全局环境光使用冷蓝灰，强度低。
- 店内使用 2-4 个暖色点光源或发光面，让橱窗内部明显亮过室外。
- 街灯使用暖黄点光源，电线杆附近加局部光晕。
- 霓虹招牌使用 emissive 材质，并配一个小范围有色光。
- 远处信号灯使用自发光材质，不参与主照明。

### 10.3 反射

- 主要积水路面使用 `Reflector`，只反射关键近景。
- 小水洼可以使用低粗糙度材质加高光贴图，避免多个反射平面。
- 如果性能紧张，改用镜面高光条纹代替真实反射，但保留地面湿润感。

## 11. 性能预算

目标以桌面端流畅、移动端可降级为准。

- 场景总三角形数量控制在合理范围，优先合并静态几何。
- 雨滴使用 `Points`，波纹使用 `InstancedMesh`，不创建大量独立 Mesh。
- 反射平面最多 1-2 个，移动端关闭真实反射。
- 使用 `requestAnimationFrame`，场景离开视口时停止更新。
- 固定 pixel ratio 上限，例如 `Math.min(devicePixelRatio, 2)`。
- 桌面优先 `60fps`，移动端优先稳定 `30fps`。

## 12. 可访问性与降级

- `prefers-reduced-motion: reduce`：关闭雨滴下落、门开合、招牌闪烁和镜头自动推进，只保留静态场景，用户仍可拖拽观察。
- 触屏设备：单指旋转，双指缩放，不依赖悬浮。
- 低性能设备：减少雨滴数量、关闭反射、降低阴影精度。
- WebGL 不可用时：显示静态 CSS 渐变背景和说明，不出现白屏。
- 场景画布使用 `aria-label` 说明这是雨夜便利店微缩模型。

## 13. MkDocs 接入与 `navigation.instant`

1. 在 `docs/index.md` 的首屏位置放置场景容器，例如 `<div id="convenience-scene" aria-label="雨夜便利店微缩模型"></div>`。
2. 在 `extra_javascript` 中注册场景入口模块。
3. 因为站点启用了 `navigation.instant`，场景模块必须兼容 XHR 替换内容区：
    - 使用 MutationObserver 检测场景容器再次出现。
    - 每次初始化前销毁旧 renderer、controls、动画循环和事件监听。
    - 离开首页时停止 render loop，避免后台消耗。
4. 场景容器样式使用 `position: fixed` 或首屏 `sticky`，需要根据最终是否覆盖正文进一步确认。
5. 场景内不放置 MkDocs 正文，正文仍放在正常 Markdown 或后续分块中。

**交付物**

- `docs/javascripts/three/convenience-scene.mjs`：入口模块（初始化、尺寸自适应、销毁）。
- `docs/index.md`：加入 import map，指向仓库内 vendored 的 three。

### 14.3 阶段 1 · 白盒街区与三个镜头（中）

**页面上能看到**：向下滚动首页，镜头从高空俯瞰缓慢下降到街角平视，再推进到便利店橱窗前；向上滚原路退回。章节文字的淡入淡出保持现在的节奏。

**交付物**

- `scene-builder.mjs`：正方形底座（约 7.2m、厚 0.18m）、便利店体块、车行道与人行道、斑马线占位、路灯与电线杆的简单位置标记。

**实现要点**

- 进度来源就用 `homepage.js` 已经写好的 `--nmd-scroll`（0–1），不要另建滚动监听；章节淡入淡出与镜头进度保持解耦。

- 滚动到顶部 / 中间 / 底部各截一张图，三张构图明显不同（能看出「看模型 → 站街角 → 望橱窗」的推进）。

### 14.4 阶段 2 · 三渲二材质、轮廓与昼夜光照（中）

**页面上能看到**：白盒变成有颜色的场景——阶梯状明暗、清晰的深色描边、店内暖黄与室外冷色的对比；切换站点主题（亮 / 暗）时，场景配色整体跟着变（亮色=白天雨天，暗色=夜晚雨天）。

**交付物**

- `materials.mjs`：1×256 的 `gradientMap`（`NearestFilter` 保证阶梯）、`MeshToonMaterial` 材质工厂、`EdgesGeometry + LineSegments` 轮廓工具（圆润物体走背面放大外壳法）。
- 灯光：冷色低强度环境光 + 店内 2–4 个暖色点光 + 街灯暖黄 + 招牌 emissive。
- 主题映射：把 `extra.css` 的 `--nmd-sky-*` / `--nmd-ground-*` / `--nmd-shop*` 等 tokens 读进 three，监听 `data-md-color-scheme` 变化（Material 把它挂在 `<body>` 上）实时换色。

**实现要点**

- 轮廓颜色用低饱和墨蓝黑（设计稿里的 `#2b3446` 一带），不要纯黑死边；远景物件可以省描边。
- 白天雨天靠亮灰蓝天光 + 白色水光反射，夜晚雨天靠冷蓝底 + 霓虹 emissive，两套只换颜色与强度，不动几何。
- 材质数量尽量合并复用，避免每个道具一份材质。
- 实测修正（2026-09-21，阶段 2 实现时发现，四条都与 three 的实际行为有关）：
    1. **分档贴图必须是 256×1 的灰度**。`MeshToonMaterial` 的分档采样是 `texture2D(gradientMap, vec2(dotNL*0.5+0.5, 0.0)).r`——只沿 **u 方向**、只取 **红色通道**。做成 1×256 或彩色分档都会退化成一片平坦明暗。实测同一颗球：本方案的 toon 材质赤道只有 3 个亮度级（177/210/242），普通 `MeshStandardMaterial` 是 47 级。
    2. **夜景反照率不能用 CSS 的 `--nmd-ground-*` 直接当材质色**。那套近黑（`#0b1120` 一带）是给 CSS 降级层做雨景渐变的，拿来当反照率会让店内暖光「没有东西可反射」，整屏死黑（实测亮暗同机位色差虽大，但夜景画面均值只有 20 余）。现在按第 4.3 节夜景表把 token 朝 `#2b3446` / `#3a4458` 抬一档。
    3. **店内需要单独一层暖白内衬**（BackSide 倒扣房间）。店面墙体的内外两面共用同一材质，夜景下若只有一层建筑材质，橱窗里会是近黑。加内衬后夜景橱窗出现「室外冷蓝 + 店内暖黄」的核心对比。
    4. **白天光照强度按 `albedo/π` 配预算**。three 的半球光 irradiance 不乘 π，而漫反射是 `albedo/π`：hemi 2.2 + key 2.0 时整屏过曝（均值 228、满屏纯白），改成 hemi 1.6 + key 1.4 后均值约 205，分档层次重新可见。
    5. 新增 `--nmd-outline`（亮 `#2b3446` / 暗 `#3a465e`）两套 token；另外 three 对 `rgba()` 会记一条 `Alpha component ... will be ignored` 警告，读取 `--nmd-shop` 这类带 alpha 的 token 时先在 JS 里剥掉 alpha，避免 Console 出现 warning。

**验收**

- 亮 / 暗两张截图差异明显：白天是浅色阴雨、夜晚是冷蓝霓虹。
- 主题切换时场景实时变色（无需刷新页面）。
- 最远机位下描边细到不糊、最近机位下不出现明显锯齿。

### 14.5 阶段 3 · 街角道具与店内陈列（大）

**页面上能看到**：便利店「有货了」——站在橱窗前能看到货架、饮料柜灯箱、收银台、关东煮柜台；街角出现自动贩卖机、自行车、雨伞架、垃圾桶、电线与电线杆。

**交付物**

- `scene-builder.mjs` 扩展：自动贩卖机、自行车（圆柱 + 圆环拼剪影）、雨伞架、垃圾桶、路牌、护栏、电线杆与电线（`TubeGeometry` 或分段圆柱）。
- `interior-builder.mjs`：货架、饮料柜（发光面）、便当区、收银台、关东煮柜台、后场门，集中在中后景。

**实现要点**

- 全部程序化几何，不引入外部模型；同类物件用 `InstancedMesh` 或合并几何，控制 draw call。
- 室内是「隔着玻璃看」的层次，细节密度低于门面：远处物件只保留剪影与色块。
- 实测补充（2026-09-21，阶段 3 实现时确定）：
    - **位置按三个机位反推**：自动贩卖机放在邻栋墙面下（`-2.2, 0.85`），进「街角」画面左侧而不进「橱窗」画面——放在店门右侧会正好压住橱窗视线；自行车、护栏、垃圾桶、雨伞架作为前景景深放在人行道近侧。
    - **省 draw call 的做法**：饮料/商品/护栏立柱这类成排物件走 `InstancedMesh`（每排 1 个 draw call，商品用实例色）；自行车车架、伞柄这类细杆用「两点连圆柱」的小工具生成，省去手算旋转；电线用 `CatmullRomCurve3 + TubeGeometry` 做垂坠。
    - **店内固装做成具名子组**（`interior:cooler` / `interior:shelf` / …），街角道具同理（`prop:vending` / `prop:bicycle` / …）。这样验收可以「逐件 `visible = false` + 截图差异」来客观证明可见性，而不是靠肉眼看图；阶段 5/6 也能按名字取用。
    - 性能实测（1440×900 一次渲染）：**105 draw call / 2554 三角形 / 312 线段 / 9 个 shader program**，远低于第 11 节的预算。
    - 验收方法：在街角机位逐件隐藏道具，7 件全部产生独立区域的画面差异（≥3 达标）；在橱窗机位逐件隐藏固装，6 类全部可见（≥4 达标）。

**验收**

- 场景三（橱窗）机位下能分辨至少 4 类室内物件；场景二能看到至少 3 件街角道具。
- 三角形总数与 draw call 在预算内（第 11 节），桌面帧率不掉到 50fps 以下。

### 14.6 阶段 4 · 程序化贴图：招牌、路牌、海报、标线（中）

**页面上能看到**：店招亮起文字，玻璃上出现海报与价签，地面出现斑马线、停车位与导视线；仓库里依然没有任何新增的 SVG / PNG 文件。

**交付物**

- `canvas-textures.mjs`：统一用 `CanvasTexture` 生成店招、路牌、海报、自动贩卖机标签、店内价签，以及斑马线、停车位、排水沟、地面导视。

**实现要点**

- 贴图统一 `colorSpace = THREE.SRGBColorSpace`，文字类贴图按实际尺寸比生成（避免拉伸模糊）。
- 招牌 / 灯箱贴图配合 emissive，夜景时自发光；白天模式降低 emissive 强度。
- 贴图尺寸能用 512 解决就不上 1024，控制显存。
- 实测补充（2026-09-21，阶段 4 实现时确定）：
    - **宽高比要按「画布 ÷ 平面」逐张核对**：运行时遍历 `material.map.image` 与 `geometry.parameters` 算出偏差，本阶段实测文字类贴图偏差 ≤1%、最大 2.2%（人行道盲道）。平铺贴图必须按「单格」宽高比算，否则 4m 长的排水沟会算出 95% 的假偏差。
    - **平铺重复次数按每格正方形取**（排水沟 22×1、盲道 15×1），否则格栅与圆点会被横向拉伸。
    - **店招/路牌用 `MeshToonMaterial` 的 `map + emissiveMap`（同一张贴图）**，`emissiveIntensity` 白天 0.5 / 夜里 1.2（路牌 0.2 / 0.65）；海报、价签、地面标线走 `MeshBasicMaterial` 的贴片工厂（不受光照），按 `nightDim` 在夜里压暗。
    - **文字贴图依赖系统字体**：验证容器里没有任何中文字体时，canvas 写出来的中文会是缺字方框（3D 场景当时还没有文字，所以前几个阶段不受影响）。本机通过 `FONTCONFIG_FILE` 指向 WSL 里的 Windows 字体解决，页面与招牌文字都能正常渲染。
    - 店招画布 1024×96 对应平面 3.96 × 0.37（10.7:1，偏差 0.3%）；实测屏幕字高：全景机位 30–40px、街角机位 52–120px，且主标题「墨海便利店」两处都完整落在画面内（橱窗机位在店招下方，招牌被顶边裁掉属正常构图）。

**验收**

- 场景一、场景二机位下店招文字清晰可读、不变形。
- `git status` 里 `docs/` 下没有新增图片文件；所有可见文字都来自运行时 canvas。

### 14.7 阶段 5 · 动效系统：雨、水、门、灯（大）

**页面上能看到**：雨持续落下、屋檐滴水、地面积水出现波纹与反光、店招与灯箱轻微闪烁、自动门偶尔开合露出店内暖光、远处信号灯缓慢变色。

**交付物**

- `rain-system.mjs`：`THREE.Points` 雨滴 + 程序化雨滴贴图；屋檐滴水（少量实例化水滴）；积水波纹（`InstancedMesh`）；玻璃雨痕（CanvasTexture UV 滚动）。
- `animation-loop.mjs` 扩展：招牌 emissive 抖动、门开合插值、信号灯循环。
- 湿地反射：`Reflector` 或低粗糙度湿面材质，移动端关闭真实反射。

**实现要点**

- 雨滴数量按视口面积与 `pointer: fine` 控制（桌面 60–100 个量级），页面不可见时暂停。
- 动效频率克制：门开合随机间隔、灯闪幅度小，不能干扰正文阅读。
- `prefers-reduced-motion: reduce` 下：雨变静态雨丝、门保持关闭、招牌恒亮、镜头不自动推进。
- 实测补充（2026-09-21，阶段 5 实现时确定）：
    - **主循环从「按需重绘」变成「持续渲染」**：阶段 1 的优化是「镜头不动就不重绘」，阶段 5 起雨每帧都在动，因此改为每帧渲染；性能杠杆回到「页面不可见 / 容器离屏即暂停」与移动端降载（雨滴 96 → 54、波纹 12 → 6、关闭真反射）。
    - **招牌闪烁的基准值必须随主题刷新**：`createAmbientEffects` 读的是 `materials.sign.userData.baseEmissiveIntensity`，而 `materials.mjs` 最初没有写这个字段——切到夜景后，闪烁会把店招 `emissiveIntensity` 从 1.2 拉回白天的 0.5，夜景招牌直接亮不起来。已在 `materials.update()` 里随主题写入该基准；实测夜景采样稳定在 1.17–1.24（偶发一次 0.85 的「小掉电」，属设计内的克制闪烁）。
    - **Reflector 走 addons 导入，必须带兜底**：`Reflector.js` 内部用裸标识符 `import 'three'`，只有在 import map 生效时可用；否则退回「高粗糙度湿面 + 高光条纹」贴片。窄屏 / 触屏档直接不做真反射（第 10.3 节的口径）。
    - **反射的代价就是降级依据**：无头 SwiftShader、1440×900 下做开关 A/B——全开 10.2fps，关掉湿地面（少一次 512×512 反射渲染）17.2fps，再关雨 17.4fps：反射约占 40% 帧时间，而 96 颗雨滴本身几乎不花钱。
    - **验收方法要换**：阶段 3/4 用「逐件隐藏 + 截图差异」依赖静止帧，下雨后该前提不成立；镜头部分改为直接读 `container.nmdScene.camera` 的位置与 fov（实测三机位间距 3.79 / 1.80 / 5.14m，回程偏差 0.000m），动效部分改为逐 0.5s 采样场景状态。
    - 实测：静置 30s 采样到 **7/7 种动效**（雨滴下落 4.79m、屋檐滴水、波纹扩散矩阵 0.88、玻璃雨痕下滑、自动门 0.68→0.06 滑开、招牌亮度抖动 0.029、信号灯绿→黄→红循环各 1.54）；reduced-motion 下主循环不启动，2s 间隔两帧差异 **0.0 / 0 像素**（完全静止），3.5s 内 7 项采样全部零变化。
    - **雨要能被截图看出来**：用「开/关 + 对照帧」而不是单看两帧差异——雨系统开/关的画面差异 155,437 像素（12.1%），而完全不做开关、仅隔 400ms 的对照帧只有 34,343 像素（其余动效的正常波动）。分项覆盖：雨滴 4.18%、积水波纹 12.15%、屋檐滴水 0.76%、玻璃雨痕 0.71%。
    - **FPS 只能在无头软渲染里给数量级**：同一份场景（136 draw call / 3.9k 三角形）在 1440×900 是 16.7fps、900×560 是 33.1fps、600×380 是 59.6fps——帧率与像素数近似线性，说明瓶颈在 CPU 光栅化的填充率而不是几何或 draw call；真实 GPU 上这个负载（3.9k 三角形 / 136 call）远高于 60fps 的余量，但仍建议在本地用 DevTools 抽样确认。

**验收**

- 静置 30 秒能观察到至少 4 种动效；截图对比能看到雨与水痕。
- 桌面 ≥50fps、移动端 ≥30fps；`reduced-motion` 下画面静止且可观察。

### 14.8 阶段 6 · 交互：拖拽、旋转、缩放（小）

**页面上能看到**：鼠标拖拽可以转动这个微缩模型，滚轮可以拉近拉远；松手后镜头缓慢回到当前滚动进度对应的位置；触屏单指旋转、双指缩放。

**交付物**

- `camera-rig.mjs` 接入 `OrbitControls`：开启阻尼、关闭平移（或限制在模型附近）、水平 ±22°、俯仰 30°–80°、缩放范围限制在「看清橱窗」到「看全底座」之间。

**实现要点**

- 用户操作叠加在滚动镜头之上：滚动只推进基础机位，拖拽偏移单独记录，松手后缓回。
- 指针事件策略：canvas 默认 `pointer-events: none`（不抢页面滚动），仅在需要拖拽时按设计文档 §6.2 的方式放开，避免移动端滚不动页面。
- 实测补充（2026-09-21，阶段 6 实现时确定，两条都是把 OrbitControls 叠在滚动镜头上才会踩到的坑）：
    - **不能每帧把基础机位写回相机**：OrbitControls 的更新是「按当前相机位置重算球坐标 → 叠加 `sphericalDelta * dampingFactor` → 写回」，如果每帧先把相机复位到基础机位，用户的增量每帧只能生效 `dampingFactor`（7.5%），实测拖 200px 只转了 0.029 rad（应为满程 0.384 rad ≈ ±22°）。改成「交互进行中相机完全归 OrbitControls，只有 `controls.target` 跟随基础目标；交互结束（最后一次指针 / 滚轮事件后 0.9s）再由相机与 target 一起指数缓动回基础机位」，拖拽立刻恢复到满程。
    - **OrbitControls 会覆盖 `touch-action`**：它的构造函数把 `domElement.style.touchAction` 设成 `none`（禁止触摸滚动），优先级高于项目 CSS 里的 `pan-y`，结果移动端竖向滑动既不滚页面也不生效。构造之后必须显式写回 `domElement.style.touchAction = "pan-y"`：竖向平移交还浏览器（页面照常滚），横向拖动与双指捏合留给 OrbitControls。
    - 指针事件门控：画布默认 `pointer-events: none`；桌面在按住 `Alt` / `Shift` 时进入交互模式（画布接管拖拽与滚轮，内容层让位，退出即恢复文字可选）；触屏不做修饰键，靠 `touch-action: pan-y` 区分「竖向滚动 / 横向旋转 / 双指缩放」，相册图片单独保留指针事件以便长按保存。
    - 角度限制按「相对基础机位」做：水平 ±22°、俯仰 ±25°（合计 50°，对应第 6.2 节的 30°–80° 区间）。三个基础机位的俯仰本身就在 77°–86°，若硬套绝对值 30°–80°，街角与橱窗机位一进入就被夹住。
    - 交互提示放在内容层（尾声段落），桌面与手机按 `pointer` 媒体特性各显示一句，场景内不出现任何提示或图标（第 6.3 节）。

**验收**

- 桌面拖拽旋转、滚轮缩放正常；移动端单指旋转、双指缩放正常且页面仍可滚动。
- 交互结束后镜头回位平滑、无回弹抖动。

镜头进度由每个 `.nmd-chapter` 在视口中的实际位置计算。章节文字不是一直可见，而是在进入视口时淡入，离开视口时淡出。

| 寄语收尾 | 0.90-1.00 | 场景三或静态收尾 | 淡入并作为结束画面 |

### 16.5 淡入淡出实现原则

- 使用章节在视口中的位置计算透明度，例如 `opacity 0 -> 1 -> 0`。
- 淡入和淡出时间保持短而柔和，例如约 `0.35s-0.6s`。
- 每个章节独立触发，不与 3D 相机的进度强绑定，避免文字闪烁。
- 移动端减少透明度变化幅度，保证阅读舒适。
- `prefers-reduced-motion: reduce` 时取消位移，只保留透明度变化或直接显示。

## 17. 3D 视角移动参考与镜头运动描述

### 17.1 可参考的滚动 3D 镜头案例

1. [Building a Scroll-Driven 3D Gallery Using a Blender Camera Path with Three.js and GSAP](https://tympanus.net/codrops/2026/07/07/building-a-scroll-driven-3d-gallery-using-a-blender-camera-path-with-three-js-and-gsap/)  
   特点：物体固定，相机沿一条预先设计好的曲线前进，滚动就像连续 dolly shot。
2. [Three.js Scroll Camera Path - GSAP ScrollTrigger WebGL Flythrough](https://fwdtools.com/ui-snippets/three-scroll-camera-path/)  
   特点：固定场景 + 相机飞行，滚动控制镜头位置，`lookAt` 目标点始终在相机前方，画面有“朝向下一个物体”的方向感。
3. [How to Build Cinematic 3D Scroll Experiences with GSAP](https://tympanus.net/codrops/2025/11/19/how-to-build-cinematic-3d-scroll-experiences-with-gsap/)  
   特点：滚动像导演指令，相机位置、目标点、文字淡入淡出和章节节奏同步编排。

### 17.2 本项目采用的镜头语言

1. **物体不动，相机动**  
   便利店、街道和道具保持固定，滚动时只移动相机，符合真实 dolly shot 的感觉。
2. **相机沿曲线路径移动**  
   使用 `CatmullRomCurve3` 或自定义关键帧曲线，让相机从全景俯瞰平滑下降到街角平视，再推进到橱窗前方。
3. **视线目标点也随路径移动**  
   相机不只是改变位置，`lookAt` 目标点会从便利店整体逐渐转向门面，再转向店内。这样会产生“正在朝下一个场景前进”的方向感，而不是机械平移。
4. **滚动即导演指令**  
   滚动进度像电影时间轴，控制相机位置、目标点、视场角，以及章节文字的淡入淡出。
5. **带轻微缓动，不完全跟手**  
   相机运动可以加入约 `0.5s-0.7s` 的平滑跟随，过滤触控板或滚轮的抖动，让移动更像镜头调度。
6. **可逆与连续**  
   向上滚动时镜头沿原路径反向回退，整个过程连续，不出现硬切。

### 17.3 三个镜头的运动描述

| 镜头 | 运动方式 | 视觉感受 |
|---|---|---|
| 场景一 | 高角度俯瞰，相机轻微环绕并缓慢下降 | 像从上方观察一个完整的微缩模型 |
| 场景二 | 相机降到人眼高度，横向绕到街角，视线跟随店招 | 像站在雨夜街角，慢慢走向便利店 |
| 场景三 | 相机继续向前靠近大玻璃窗，视线转入店内 | 像走到窗边，向明亮温暖的店内张望 |
