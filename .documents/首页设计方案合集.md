## 2. 官方 Home 页面实现（复刻方案）

### 2.1 实现原理

官方 demo 首页（squidfunk.github.io/mkdocs-material/）不是用 Markdown 写的，而是**自定义 HTML 模板**，由 3 个文件配合：

| 文件 | 作用 |
|------|------|
| `mkdocs.yml` | `theme.custom_dir: overrides` 声明自定义模板目录 |
| `docs/index.md` | frontmatter 写 `template: home.html`，指定该页用自定义模板 |
| `overrides/home.html` | 继承 `main.html`，在 `tabs` 区块注入 hero，并清空内容区和页脚 |

### 2.2 配置（`mkdocs.yml`）

```yaml
theme:
  name: material
  custom_dir: overrides   # ← 关键：让 MkDocs 优先使用你的自定义模板
```

### 2.3 首页标记（`docs/index.md`）

```markdown
---
template: home.html     # ← 首页改用自定义模板渲染
---

Welcome to Material for MkDocs.
```

### 2.4 核心模板（`overrides/home.html`，官方原版源码）

```jinja
{% extends "main.html" %}
{% block tabs %}
  {{ super() }}
  <style>.md-header{position:initial}.md-main__inner{margin:0}.md-content{display:none}
  @media screen and (min-width:60em){.md-sidebar--secondary{display:none}}
  @media screen and (min-width:76.25em){.md-sidebar--primary{display:none}}</style>
  <section class="mdx-container">
    <div class="md-grid md-typeset">
      <div class="mdx-hero">
        <div class="mdx-hero__image">
          <img src="assets/images/illustration.png" alt="" width="1659" height="1200">
        </div>
        <div class="mdx-hero__content">
          <h1>Technical documentation that just works</h1>
          <p>{{ config.site_description }}</p>
          <a href="{{ page.next_page.url | url }}" class="md-button md-button--primary">Quick start</a>
          <a href="{{ 'insiders/' | url }}" class="md-button">Get Insiders</a>
        </div>
      </div>
    </div>
  </section>
{% endblock %}
{% block content %}{% endblock %}
{% block footer %}{% endblock %}
```

### 2.5 实现要点说明

- **继承与覆盖**：`{% extends "main.html" %}` 继承主题主模板；`block tabs` 注入 hero 部分；`block content` 和 `block footer` 置空。
- **隐藏正文**：内联 CSS `.md-content{display:none}` 隐藏正文内容区，`.md-sidebar--primary/secondary` 在桌面端隐藏两侧边栏，`.md-header{position:initial}` 让顶部导航栏不再置顶吸顶。
- **hero 样式**：`mdx-hero` 等样式类**不在主题包里**（官方 demo 站专属），需要自己写 CSS 定义图片与文字的布局（如 flex 双栏、响应式）。
- **来源**：官方仓库 https://github.com/squidfunk/mkdocs-material 的 `material/overrides/home.html`（master 分支，2026-08 抓取）。

### 2.6 本项目的落地方案（待实施）

## 2. 思考分析

### 2.1 awesome design.md 是什么（网读结论）

- **DESIGN.md** 是 Google Stitch 提出的「纯文本设计系统文档」：一份 markdown，让 AI 代理读完即可生成视觉一致的 UI。
- **awesome-design-md** 仓库（MIT，73+ 个品牌）收录了真实网站的设计分析，每份包含 9 大板块：
  1. Visual Theme & Atmosphere（视觉主题与氛围）
  2. Color Palette & Roles（语义色板 + hex）
  3. Typography Rules（字体层级全表）
  4. Component Stylings（按钮/卡片/输入框等状态）
  5. Layout Principles（间距体系、栅格、留白哲学）
  6. Depth & Elevation（阴影系统、表面层级）
  7. Do's and Don'ts（设计红线）
  8. Responsive Behavior（断点、折叠策略）
  9. Agent Prompt Guide（给 AI 的提示词）

**启示**：本项目不是照抄某品牌，而是**先用 DESIGN.md 方法论产出一份「墨海寻珠」自己的设计系统文档（第 7 节）**，再按此实现 —— 这正是 awesome design.md 推荐的工作方式。

### 2.2 三个组件库的调研结论（已上网核实）

| 库 | 可借鉴的组件/效果 | 本站（静态 MkDocs）可落地形式 |
|---|---|---|
| **React Bits**（140+ 组件） | Aurora 极光背景、GradientText 渐变文字、TiltedCard 倾斜卡片、SpotlightCard 聚光灯卡、ScrollReveal 滚动显现、粒子背景 | 全部降级为 **纯 CSS keyframes + 原生 JS**（站点无 React，但效果原理通用） |
| **Aceternity UI** | Bento Grid 网格卡片、Spotlight 卡片、Timeline 时间线、3D 卡片、Hero 区块、HoverBorderGradient | Bento 布局用 CSS Grid；时间线用 flex + 渐变线；Spotlight 用 mousemove 原生 JS |
| **Uiverse.io**（3000+ 元素，MIT） | 玻璃拟态卡片、渐变光环头像、hover 动效、时间线、徽章 chip | 直接以 CSS/HTML 形态复用思路，样式自写以匹配主题色 |

**关键约束**：站点是 MkDocs + Material（静态站、已有樱花粉/深紫主题），无 React、无 Tailwind、无构建工具 —— 所有「React 组件」只能提取其**视觉与交互理念**，用 HTML + CSS + 少量原生 JS 实现。

### 2.3 站点现有基础（项目分析）

- 主题：Material，**樱花粉 primary + 深紫 accent**（亮色），暗色黑底粉链；支持明暗自动切换 ✅
- `docs/stylesheets/extra.css` 已挂载（当前为空注释）
- `docs/javascripts/` 已有 mathjax.js / mermaid.mjs / extra.js
- 历史文档已规划过「官方 home.html 模板方案」（custom_dir + overrides/home.html）**但未实施**，overrides 目录不存在
- 首页现有图片 5 张：我的照片1/2/3.jpg、大师合影.jpg、获奖证书.jpg（在 `docs/主页/`）

**方案决策**：放弃 overrides/home.html 全模板方案（内容写死在模板里，编辑成本高、无法参与全文搜索），改用 **HTML 分块嵌入 markdown + extra.css 定制 + 少量原生 JS**：
- 正文内容保留在 `index.md`，易于维护 ✅
- 内容仍参与站点搜索 ✅
- 页面级隐藏 TOC 用 frontmatter `hide: [toc]` ✅

### 2.4 设计方向定调

「墨海寻珠」= 知识如海、寻珠采撷。主题色已是樱花粉 × 深紫。定调为：

> **「书卷 × 樱色」编辑风**：衬线大标题（宋体系衬线字栈，不用外链字体）承载书卷气；樱花粉极光渐变背景 + 玻璃拟态卡片承载现代感；深紫作点缀强调 —— 暗色模式整体转墨色，粉色化为微光。

不引入外部字体（国内网络不稳 + 主题已用 Roboto），用系统字体栈：`Georgia, "Noto Serif SC", "Songti SC", "SimSun", serif` 用于展示标题；正文跟随主题默认。

## 9. Bug 修复记录（2026-08-11，第二轮）

### Bug 1：点击「主页」显示空白，刷新后正常

**现象**：从其他页面点击导航「主页」（`navigation.instant` 生效）→ 内容区空白；F5 刷新后正常。

**根因分析**（两步定位）：
1. **交互层面**：滚动显现机制 `.nmd-reveal { opacity: 0 }` 由 CSS 隐藏，靠 homepage.js 加 `is-visible` 显现。首页全部 5 个分块都挂了 `nmd-reveal`，含 Hero。
2. **主题机制层面**：`navigation.instant` 下点击链接是 XHR 替换内容区（`data-md-component` 容器），`extra_javascript` 里的脚本**只在整页加载时执行一次，instant 导航后不会重执行**（已核查 material 9.7.7 源码：无 `locationchange` 类完成事件可监听；`base.html:254` 注入的脚本不随 XHR 重跑）。
3. **叠加结果**：instant 替换后 CSS（首屏已加载，持续生效）仍在隐藏 `.nmd-reveal`，而 JS 不重跑 → 无 `is-visible` → 整页永远透明 → **空白**。刷新触发整页加载 → JS 正常跑 → 正常。

**修复方案**（双保险）：
- `docs/javascripts/homepage.js` 重构：
  - 抽出 `initHome()`（打字机/滚动显现/聚光跟随），以 `hero.dataset.nmdInit` 保证同一 DOM 实例只初始化一次；
  - 新增 `MutationObserver` 监听 `<html>`（永远不会被 instant 替换）下的节点插入——内容区被 XHR 替换后检测到新 `.nmd-hero` 即自动重新初始化；
  - 计时器与 IntersectionObserver 实例跨初始化清理（`clearTimeout` / `io.disconnect()`），防止重复叠加。
- `docs/stylesheets/extra.css` 第 8 节：隐藏态改为 `html.nmd-js .nmd-reveal` 作用域——`.nmd-js` 类由 homepage.js 同步添加，**任何 JS 未执行的场景都不会白屏**（无 JS 兜底）。

**验证**：本地起服务 + headless Chrome 跑「JS 先加载、内容后注入」的 harness（等价 instant 替换）→ hero 自动显现 `is-visible` ✅、打字机启动 ✅、视口外元素保持隐藏（滚动显现语义正确）✅。

### Bug 2：主页左侧导航栏不应显示

**根因**：首页 frontmatter 只写了 `hide: [toc]`，未隐藏左侧导航。

**修复方案**：`docs/index.md` frontmatter 增加 `navigation`（material 原生支持，`base.html:157` 会给 `.md-sidebar--primary` 加 `hidden` 属性）：

  - toc        # 首页隐藏右侧目录

**验证**：构建产物检查——主页 `.md-sidebar--primary` 带 `hidden` ✅；其他页面（读书笔记）无 `hidden`，导航栏正常显示 ✅；移动端汉堡抽屉不受影响（主题默认行为）。

**改动文件**：`docs/javascripts/homepage.js`（重构）、`docs/stylesheets/extra.css`（第 8 节）、`docs/index.md`（frontmatter）；`mkdocs build` 通过（13.9s）。

用户反馈图片仍偏大。方案：`.nmd-fig-media` 增加 `max-width: 280px` + `width: 100%`（列内自适应），偶数行（右置图片）加 `justify-self: end` 贴右对齐避免悬空。网格列宽保持 `1fr : 2fr` 不变，文字区充分舒展。重建 + 截图确认三行图片均收缩至 280px 上限、对齐正常。

### 第四轮补充 2：图文空白修复（文字自动适配）

用户反馈：图片缩小后，1fr 图片列在宽屏下宽于图片本体，图片与文字之间留出大片空白。

根因：`grid-template-columns: 1fr 2fr` 的图片列按比例取宽（大屏可达 400px+），而图片被 `max-width: 280px` 限制 —— 列宽 ≠ 图宽，剩余空间悬空。

修复：改用 **auto 列** —— `grid-template-columns: auto minmax(0, 1fr)`，图片列精确等于图片实际宽度（`width: 280px; max-width: 100%`），文字列占满剩余全部宽度、自然换行；删除不再需要的 `justify-self: end`。重建 + 截图确认三行图文间仅剩 28px 固定间距，宽屏下文字区最大、自动换行，无任何空白悬空。

## 13. 第六轮：关于我「只显示大师合影」真根因 + 我的照片 Coverflow 轮播

### 13.1 用户反馈（连续三轮迭代）

1. **第一反馈**：「关于我」区域本应有三张照片，但只显示大师合影（本地打开，与推送无关）
2. **第二反馈**：把未显示的两张照片独立成组件、放在项目缘起后面
3. **第三反馈**：照片改为 photo gallery 循环播放，去掉标题
4. **第四反馈**：轮播要有开门/框/翻牌等切换效果，前一项和后一项降低透明度，避免单框太单薄留白过多

### 13.2 真根因诊断（推翻第五轮 GitHub Pages 结论）

用户明确「本地打开、与推送无关」，故第五轮的 GitHub Pages 编码假设不适用于本次。用 headless Chrome 对本地服务实测 `getBoundingClientRect`：

| 图片 | 修复前渲染 | 原因 |
|---|---|---|
| photo-1.jpg（第 1 行） | **figure 2x2（塌陷）** | 被 `:nth-child(even)` 误判为偶数行 |
| photo-master.jpg（第 2 行） | 280x210 正常 | 奇数行留在 `auto` 列 |
| photo-2.jpg（第 3 行） | **figure 2x2（塌陷）** | 同 photo-1 |
| certificate.jpg（特长卡） | 163x218 正常 | 不受 fig-row 影响 |

**根因**：`extra.css` 第 5 节 `.nmd-fig-row:nth-child(even) .nmd-fig-media { order: 2 }` 的奇偶选择器被 `<h2>` 标题干扰——section 第一个子元素是 `<h2>`（占第 1 位），导致第 1、3 个 fig-row 被误判为「偶数行」，图片被 `order: 2` 排进 `minmax(0, 1fr)` 弹性列，该列被长文本撑满后宽度为 0，`max-width: 100%` 把图片压成 0x0。非「照片太大」。

**修复**：`nth-child(even)` → `nth-of-type(even)`（只数同类型 div 兄弟，不受 `<h2>` 干扰），偶数行改为 `grid-template-columns: minmax(0, 1fr) auto` 列模板（图片留在 auto 列，永不被弹性列压塌）。

### 13.3 迭代实现记录

**迭代 A（独立组件）**：`docs/index.md` 新增 BLOCK 3 · 我的照片（项目缘起之后），`.nmd-photo-grid` 双图并排（photo-1 / photo-2）；「关于我」删除两个塌陷 figure，三组文字合并为 `.nmd-fig-copy-full` 全宽文字块，保留合影行 + 特长卡证书。

**迭代 B（纯 CSS 无缝轮播）**：`.nmd-photo-grid` → `.nmd-gallery` 轨道式轮播——4 个 slide（3 图 + 复制首图）在 400% 宽轨道上 `translateX` 0→-75% 后跳回 0%（复制首图保证视觉无缝），18s 循环；去掉「我的照片」标题（用户要求）；`prefers-reduced-motion` 下停动画显示首图。

**迭代 C（Coverflow 封面流）**：删除轨道结构，改为 **3 张照片各带独立循环动画 + 负延迟错开 1/3 周期**（delay 0s / -6s / -12s，总周期 18s）：

- 同一时刻：中间照片完整展示（opacity 1、z-index 3），左右两侧各露出前一张 / 后一张（opacity 0.45、scale 0.8、`rotateY(±28deg)` 倾斜、z-index 2）→ 画面饱满无空白
- 切换动画：照片 `translateX` 位移 + `rotateY` 翻转 + 透明度渐变（0→0.45→1），呈现「开门/翻牌」过渡；53%/60% 处经 opacity 0 瞬移完成左右侧循环

- 响应式 <720px：容器压至 300px、slide 加宽至 76%
- `prefers-reduced-motion`：轮播停为**静态封面流**（三张同时可见，中间高亮两侧半透明），不再白屏

## 14. 第七轮：Hero 全屏化（首屏沉浸式）

### 需求

用户反馈：首页 Hero 背景被限制在内容容器（`.md-grid` max-width 61rem）内的圆角卡片里，像「一个方框」。要求：背景铺满整个屏幕（全宽全高），但**全屏只作用于第一屏**，往下滚动到「项目缘起」等区块时恢复正常的居中布局。

### 分析（MkDocs Material 布局实测数据）

- 页面结构：`<header>`（sticky，top:0，2.4rem）→ `.md-tabs`（非 sticky，随滚动滚走，仅 ≥1220px 显示）→ `.md-main` → `.md-main__inner.md-grid`（61rem 居中，margin-top 1.5rem）→ `.md-content__inner`（左右 1.2rem 边距 + padding-top .6rem + `::before` 高 .4rem）→ `.nmd-hero`
- 方框感来源：hero 被 61rem 限宽 + 内容边距 + 自身 26px 圆角 + 整圈描边/阴影框死
- 全屏方案：`width:100vw + margin-inline:calc(50% - 50vw)` 破容器（文章列水平居中、边距对称，50% 与 -50vw 恰好抵消）——数学已验证
- 两个易错点：
  1. **100vw 滚动条问题**：100vw 含滚动条宽度而布局视口不含（经典滚动条系统差 15~17px），纯 CSS 无法感知 → JS 写入 `--nmd-sb`
  2. **主题顶部预留空隙**：`.md-main__inner`/`.md-content__inner`/`::before` 三处共约 2.5rem，不清理 hero 贴不住 sticky header → `:has(.nmd-hero)` 作用域清零

### 实现记录

**extra.css**：
- 第 3 节 `.nmd-hero` 重构：`width:calc(100vw - var(--nmd-sb, 0px))` + `margin-inline:calc(50% - 50vw + var(--nmd-sb, 0px)/2)`；`min-height:calc(100svh - 2.4rem)`（≥1220px tabs 可见时 -4.8rem）；flex 纵向布局；圆角仅 `0 0 44px 44px`；边框仅底边；去整圈卡片阴影；`padding:clamp(56px,10vh,96px) clamp(20px,4vw,36px) 0`
- `.nmd-hero-inner`：`flex:1 1 auto` + `justify-content:safe center` 垂直居中（内容超高退回顶部对齐防裁切）
- `.nmd-scroll-hint`：`margin-top:0` + `padding-bottom:clamp(20px,4vh,36px)` 钉底
- 新增 3.1 节（`:has` 作用域，仅首页生效）：`.md-main:has(.nmd-hero)` 下 `.md-main__inner{margin-top:0}` / `.md-content__inner{padding-top:0}` / `::before{display:none}` 清零顶部空隙；`overflow-x:clip` 防横向溢出（clip 不破坏 sticky，区别于 hidden）
- 第 9 节移动端：`.nmd-hero` padding 底部归 0

**homepage.js**：新增 `setViewportVars()` —— 写入 `--nmd-sb`（`window.innerWidth - documentElement.clientWidth`），初始 + resize 同步；与既有「原生 JS 微交互」模式一致

### 验证记录（headless Chrome 数值断言）

桌面 1280×800：hero left=0 / right=布局视口宽（精确贴边）✅、顶部贴住 header(48px)+tabs(48px) ✅、首屏精确填满（bottom=800=视口高）✅、内容垂直居中 ✅、滚动提示钉底 ✅、无横向溢出 ✅
窄屏（tabs 隐藏）：全宽 + 填满首屏（内容超高时 hero 自然增高）✅
暗色（注入 html+body `data-md-color-scheme=slate`）：hero 背景切为墨色渐变 `rgb(33,27,44)`，全部 slate token 生效 ✅
子页面（读书笔记）：无 `.nmd-hero` → `:has` 不命中 → `.md-main__inner` margin 30px / overflow visible / padding 12px，布局完全不变 ✅
`mkdocs build` 通过（退出码 0）

**说明**：Material 将 `data-md-color-scheme` 同时设在 `<html>` 与 `<body>`，子元素继承 body 层级 —— 验证暗色须两处同时注入（headless `--force-dark-mode` 在现行 Chrome 已不翻转 prefers-color-scheme，改用属性注入）。

## 4. 分镜时间轴（首屏 9 秒）

建议总时长 8~10 秒，默认 9 秒。

### Phase A（0.00s - 1.20s）冷开场

- 背景近黑，仅保留低频光感
- 轻微扫描线或噪点（克制）
- 主标题尚未完全显影

### Phase B（1.20s - 3.40s）显影建立

- 标题从 blur + opacity 渐入
- 头像光环建立，副标题进入
- 徽章/CTA 仍抑制，避免抢焦点

### Phase C（3.40s - 5.80s）单镜头推进

- Hero 整体轻推近（dolly-in 幻觉）
- 前中后景分层视差（近景快，远景慢）
- 视觉重心固定在标题与头像区域

### Phase D（5.80s - 7.20s）强节奏转场

- 三选一主转场：
	- 开门（split-door reveal）
	- 翻牌（card-flip wipe）
	- 擦除（directional mask wipe）
- 要求：同一时刻只保留一种主语法

### Phase E（7.20s - 9.00s）回归内容流

- 动效密度下降约 70%
- 项目缘起区块接管视觉主导
- 阅读节奏优先，卡片动效仅保留 hover 级反馈

实现约束为静态站可落地方案：HTML + CSS + 原生 JavaScript，不依赖 React。

---

## 7. 提示词增强短语库（按需拼接）

### 7.1 镜头感增强

Use a continuous camera path illusion, subtle dolly-in, and layered depth cues with near-mid-far motion differentials.

### 7.2 玻璃霓虹增强

Use translucent glass panels with edge highlights, neon accents in pink-violet-cyan, and restrained bloom on dark matte backgrounds.

### 7.3 转场增强

Transitions must feel editorial and intentional, with one dominant transition per phase and no overlapping competing transitions.

### 7.4 可读性增强

After the hero sequence, reduce animation density by 70%, increase text contrast, and prioritize scanning rhythm for long-form reading.

### 7.5 工程落地增强

Keep first meaningful paint clean, cap heavy effects to hero only, and avoid continuous full-page expensive animations.

## 8. 技术边界与实现约束（针对本项目）

项目约束：

- 站点框架为 MkDocs Material
- 首页内容以 docs/index.md 为核心
- 样式集中在 docs/stylesheets/extra.css
- 交互集中在 docs/javascripts/homepage.js
- 不依赖 React / Tailwind / 构建链重构

实现原则：

1. 首屏强动效仅限 Hero 区
2. 正文区只保留轻量反馈（hover / reveal）
3. 动画属性优先 transform、opacity、filter
4. reduced-motion 必须全链路可用
5. 保持明暗主题 token 一致性

## 9. 性能预算（建议）

- 首屏额外 JS：<= 40~60KB（压缩后）
- 首屏核心动画时长：8~10 秒
- 首屏持续高频动画对象：<= 4 类
- 首屏结束后 CPU/GPU 压力显著下降

禁止项：

- 不在全文区持续运行高成本粒子
- 不引入无降级的重型 WebGL 依赖
- 不让多个主转场同屏竞争

## 10. 验收标准（设计层）

满足以下条件视为设计达标：

1. 用户首次进入首页，能够明显感知“片头开场”而非普通 Banner
2. 视觉焦点在首屏时间轴中始终可追踪
3. 开门/翻牌/擦除至少有一种呈现明确且不混乱
4. 首屏结束后阅读感显著提升，不被持续动效干扰
5. 在 reduced-motion 下页面仍完整、优雅、可读

建议按三阶段推进：

1. Phase 1（低风险）：统一首屏时间轴 + 单一主转场
2. Phase 2（增强）：加入分层视差与镜头推进
3. Phase 3（打磨）：节拍校准、细节统一、性能压测

每阶段完成后都进行一次：

- reduced-motion 验证
- 移动端验证
- 首屏性能验证

本定稿的核心不是“多”，而是“准”：

### 4.2 可读性回落

### 4.3 性能优化

- 控制持续动画对象数量

- 动效观感高级但不“吵”

## 5. 动效语法优先级

首发只实现一种主转场，建议顺序：

1. 开门（split-door）
2. 擦除（directional wipe）
3. 翻牌（card-flip）

原因：

- 开门最稳，视觉语义清晰
- 对静态站实现成本最低
- 最容易做 reduced-motion 降级

### 风险 2：instant 导航重复初始化

规避：

- 继续沿用数据标记与观察器清理机制

### 风险 3：移动端性能波动

规避：

- 小屏降级 blur、减少粒子和阴影
- 触控设备禁用高频鼠标跟随逻辑

### 风险 4：无障碍可用性不足

规避：

- 全量支持 prefers-reduced-motion
- 保证键盘可达与文本对比度

### 3.1 三种形态对比

| 形态 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| A. 单仓库双构建（推荐） | 仓库内 `home/`（React）与 `docs/`（MkDocs）并存；MkDocs 构建到 `site/notes`，React 构建到 `site/` 根目录，统一发布 | 一个仓库、一套工作流、内容与主页同源管理 | workflow 改造复杂度中等；需处理 base path |

```text
repo/
├── home/                  # React 主页（本方案新增）
│   ├── src/
│   └── dist/ -> site/
├── docs/                  # 既有 MkDocs 笔记内容
├── site/                  # 构建产物（gitignore）
│   ├── index.html         # React 主页（根路径）
│   └── notes/             # MkDocs 笔记站（子路径）
└── .github/workflows/gh-pages.yml   # 双构建改造
```

关键配置点：

- MkDocs：`site_dir: site/notes`、`site_url` 与 `use_directory_urls` 需按子路径调整

> ⚠️ 实施前需确认：① GitHub Pages 是 `user.github.io` 根域名还是项目页路径；② 笔记站是否接受 `/notes/` 子路径。这两个决定直接写入构建配置。

2. 实现与已批准概念图 fidelity 10/10：拷贝、布局、色彩、字体、间距、容器模型、动效逐项一致
3. `prefers-reduced-motion` 下全部动画降级，页面完整可读、可操作
4. 移动端无横向溢出、无元素重叠，触控交互可用
5. 首屏额外 JS ≤ 既定预算；高频动画以 `transform` / `opacity` 为主；片头结束后面 GPU 负载显著下降
6. 四类笔记链接全部可达，无 404；`/notes/` 子路径在根域名与项目页两种场景下验证
7. `tsc` / `vite build` 通过，控制台无报错，键盘可达性通过基础检查

| 区块 | 布局 | 内容 | 动效 | 交互/状态 |

| 照片墙 | 轮播或网格（以概念图为准） | 4 张生活照 | 自动/手动切换 | 缩略图导航 |
| 学历时间线 | 垂直时间线 | 5 个阶段，当前高亮 | 滚动显现 | 当前节点发光 |

| 寄语与联系 | 收尾卡 | 寄语 + 社交链接 | 淡入 | 回到顶部 |
| Footer | 单行/双行 | 版权 + 链接 | 无 | — |

### 3.4 分镜时间轴（9 秒，沿用设计定稿）

| Phase | 时间 | 实现要点 |
|---|---|---|
| A 冷开场 | 0.00–1.20s | 近黑背景 + 低频扫描线，标题未显影 |
| B 显影建立 | 1.20–3.40s | 标题 blur+opacity 渐入，头像光环建立 |
| C 单镜头推进 | 3.40–5.80s | 分层视差 dolly-in，焦点在标题/头像 |
| D 强节奏转场 | 5.80–7.20s | 单一主转场（开门/翻牌/擦除三选一） |
| E 阅读回落 | 7.20–9.00s | 动效密度下降 70%，正文接管 |

### 3.5 响应式与可访问性

- 断点沿用 Tailwind 默认（sm/md/lg/xl）；Hero 字号用 `clamp()`
- `prefers-reduced-motion: reduce`：跳过 Boot 与片头，停用粒子/Glitch/扫描线，保留静态呈现
- 所有交互元素可键盘聚焦，焦点环可见；图片提供 `alt`；对比度达 WCAG AA
- 中文正文行高 ≥ 1.75，正文最小字号 16px
